# 统一证据与候选分析队列

2026-10-12实施。当前阶段仅本地证据、候选及有限真实联调；没有CRM写入执行器，没有接入Twenty统一待审核页面，也没有自动持续调用模型。

`scripts/signal_queue.py`把邮件数据库与WhatsApp当前版本规范化到受ACL保护的`records/chat-signal/signal.sqlite3`。保留来源、收发方向、原身份、发生时间、内容版本、完整性和已核实客户绑定。原始媒体凭据不复制到模型输入；图片内容仍未下载，未完成识别。未知时间不使用导入时间替代。

邮件只按入站的唯一真实From或出站的唯一直接To匹配；多收件人不猜唯一客户。系统邮件标记只用于本地候选筛选，不删除原文。未知身份不自动当新客户或供应商；来源已采集不表示已分类为客户采购。WhatsApp按确切会话标识匹配已核实绑定，当前没有核实的客户WhatsApp绑定，因此这部分暂未进入模型任务。

已验证身份、可读完整文字进入按客户组织的分析单元。客户归属不等于采购归属；模型必须逐条覆盖原消息，对每条分别标明采购候选、客户资料、无变化或归属不明。合并同一客户上下文不代表合并订单。任务身份包含工作区、客户、证据集合、规则版本、身份版本、模型及步骤；成功任务复用，不重复调用。旧内容或身份改变后依赖任务和候选失效；邮件同Message-ID异内容只是不同证据，不凭此猜编辑。

HTTP调用之前SQLite事务持久领取尝试；同任务最多3次含首次，客户端无隐式重试。并发重复领取拒绝，进程中断不清次数，10分钟未完成的领取由后续同步标记等待重试或最终失败。相同任务的后续重试目前需明确任务ID发起；后台定时器仅同步证据和候选任务。没有任务时无模型调用。系统异常与业务候选分开存储；尚未部署用户界面，不能称失败已在Twenty通知。

模型接口只允许已授权的DeepSeek官方端点。调用上限按完整语义单元校验，超出50000字符需要语义拆分，不能静默截断。当前真实客户上下文适配只实现Diana；其他客户上下文、陌生实质询盘识别、三步骤小结和正式审核/写入链仍待实施。

候选输出只保存，不执行。完整覆盖及证据引用校验独立进行；模型confidence不当成业务正确性证明。没有拟变更、采购归属明确无变化的历史问题保存为`historical_context_only`，不成为当前业务待办。原模型输出仍完整保存用于诊断。真正归属不明的实质采购与拟变更问题保留候选。

# 阿里导出文件夹接入（只读）

2026-10-12 已部署，用户选择“先完成只读处理与更新清单”。不创建新 API 密钥、不修改 CRM，不使用 T2 或聊天专用密钥。

## 使用方法

1. 在阿里所有订单页导出原始 XLSX。
2. 把文件放进 `K:\CRA客户项目\阿里导出接入`，或双击项目根目录“阿里导出接入文件夹.lnk”。
3. 电脑保持登录、已有 Twenty 服务可用时，后台约每分钟检查一次。
4. 双击项目根目录“阿里导出核对清单.lnk”，查看 `records\ali-export\最新核对.html`。页面列出生成时间、客户和订单建议及需要核实的差异。

当前自动的是文件读取、归档、去重及 CRM 对照。阿里导出操作仍由人执行；没有部署自动浏览器点击、聊天采集或实时物流读取。只读程序也不会发客户消息。

## 运行和保护

- 任务：CRA-Wingcore-Ali-Export-Reader，当前用户登录及每分钟，IgnoreNew，最长3分钟。
- 隐藏 pythonw.exe 启动；WSL 命令 CREATE_NO_WINDOW；没有 PowerShell 每分钟弹窗。
- 标准库读取 XLSX 原始 XML，忽略原导出的错误 A1 维度元数据，订单号保留为文本，科学计数法字符串拒绝。
- 文件大小最多20MiB，解压内容最多100MiB，限制单表及预期字段；不执行公式、宏或工作簿内的指令。
- 新文件稳定5秒后读取，读取后再次核对哈希；同内容只处理一次。每份原表、逐行来源和候选以 SHA256 归档。
- CRM 只用现有本地数据库的 READ ONLY 事务读取。程序无任何写入 SQL、REST 写入或模型请求代码。
- 商品行按订单号聚合，订单金额只取一次。同号字段冲突、CRM重复订单号、客户归属不一致则列为问题，不静默选第一条。
- 客户邮箱不同/已关联其他客户不覆盖；不把收货国家当买家国家，不把电话当 WhatsApp，不把合同预付款当到账。
- 收款、补差、退款、履约成功、原单金额及跟进日期不被导出自动覆盖。合同运费只作建议，不推断货代实际成本。
- 没有运单号或完整轨迹的内容留空；时间未给时区的保留原文，不能直接用于逾期计算。
- 待同步订单保留 record_id 及 expected_updated_at 供将来的正式执行器并发核验；当前清单不是可直接执行的批准计划。

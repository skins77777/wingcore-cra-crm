## 1. 安全边界

调用链固定为：

```text
报价前端（Twenty 当前登录会话）
  → 认证报价函数 /s/cra-quotes/read 或 /s/cra-quotes/register
  → Python 报价接口（专用通信 Token + 可信 workspaceMemberId）
  → Twenty（只在 Python 后台保存并使用报价 API Key）
```

- Twenty API Key 只存在 Python 后台的受保护配置，不进入前端或 Twenty 应用变量。
- 报价通信 Token 只存在服务端函数和 Python 后台；浏览器不得访问。应用变量设为 Secret。
- 前端只使用两个报价函数。读写请求不接受任意 Twenty 路径、GraphQL、字段映射或登记人覆盖。
- 认证函数从 `context.workspaceMemberId` 获取成员，函数和后台各自检查明确的商机范围。后台验证通信 Token 与 Workspace。
- 后台仅生成三字段 CRM PATCH，自动 `updatedBy` 更新由 Twenty 完成；调用方提交业务字段或系统审计字段均拒绝。
- REST 上游附带的名称在后台读取适配器被丢弃，后台不将完整 Opportunity 或上游错误正文返回浏览器。
- 可信服务端必须隔离通信 Token 与 Key。拿到通信 Token 的服务端能够代表配置中的成员；白名单无法防护后台主机或这些凭据本身被控制。

## 2. quote_entry.py 检查与修正

| 检查项 | 当前结果 |
|---|---|
| 原始远端读取 | 原实现返回整个 `data.opportunity`，已在本地修正 |
| 固定读取 | `QuoteRemote.read` 恰好保留六字段，任一必要字段缺失时拒绝处理 |
| 六字段 | id、updatedAt、deletedAt、craT1QuoteRound、craT1QuoteSentAt、craT1QuoteEvidence |
| CRM 更新字段 | `QuoteRemote.update` 要求字段集合恰好等于三个报价字段，否则拒绝 |
| 用户登记请求 | 允许提交编号、商机 UUID、状态、版本、报价事实、渠道等业务表单字段；不能自由提交 CRM 字段名 |
| 字段生成 | `target_fields` 由已验证事实生成固定三字段，不把用户 body 作为 Twenty PATCH |
| 任意字段透传 | 未提供通用接口；未知字段在函数和后台均被拒绝 |
| 读取响应 | `QuoteService.get` 返回版本、三个 T1 字段及登记业务记录，不返回 raw Opportunity |
| 错误处理 | 返回固定错误码，不返回上游正文、认证头或 Key |
| 网络重定向 | 已在本地禁止 Twenty HTTP 重定向，避免认证头跟随跳转 |

注意：“固定六字段”指远端记录进入业务层时的允许字段集合。报价 HTTP 接口不是直接返回六键原始商机；它另外包含提交状态、登记人和处理结果等本地登记信息。`deletedAt` 用于拒绝删除目标。该业务响应中没有商机名称、金额、阶段、公司或联系人透传。

## 5. 已知限制与适用范围

1. Twenty v2.45.0 强制允许读取 Opportunity.name。后台会收到并丢弃该字段，前端不取得它；不能宣称原生 Key 自身满足六字段读取权限。按照本阶段明确接受的后台边界，此限制不再单独阻止生产准备，不继续修改 Twenty 权限模型。
2. 报价更新依赖 updatedBy 的系统更新权限。应用拒绝用户提交它，但持有上游 Key 的可信服务端仍处于原生权限范围内。
3. 商机范围由服务端双层显式名单限制，不能据此声称 Twenty Key 自身只有单行权限。首次生产测试不使用 `"*"`。
4. 当前应用 SDK 为 2.41.0，目标 Twenty 为 2.45.0。本地类型检查和构建已通过，但实际函数 URL、部署后的认证上下文和 Secret 可见性仍需正式接入验收。
5. Customer、Order 独立对象未存在于隔离 Workspace；不能把对象不存在错误算成权限拒绝通过。对象隔离实测范围为 Company、Person、Task；生产角色及其他对象范围仍需创建 Key 前核对。
6. 后台与 Twenty 没有跨系统事务，通过持久恢复计划、updatedAt 条件和回读保证恢复；生产备份/恢复及 T1 扫描联动还需验收。
7. 后台复用审核服务进程。源码更新不等于运行进程已加载新代码，后续受控接入需重启，并验证已有审核路由正常。

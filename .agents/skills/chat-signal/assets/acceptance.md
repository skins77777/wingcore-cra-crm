## 运行位置与公网入口验收

- VPS 版：实际服务和配置证明业务接收、持久数据、任务调度、分析编排、审核与写入均在 VPS，模型是出站 API 调用；网关仅转发，无另一套业务 Cron/队列重复处理。不能仅凭配置文件或一个网址判通过。
- 本地版：记录实际运行依赖、启动方法、电脑/Docker/网络及隧道的持续运行要求；休眠与恢复影响依据实测说明，不套用历史混合云结论。
- 采用公网入口时，从外部网络验证 Twenty 登录、刷新、数据保存、附件上传下载、所需实时连接和回调鉴权；同步 SERVER_URL 及采用的回调地址，私密响应不公共缓存。
- Vercel/GPT 站点分别记录平台到源站可达性与所需协议能力，API 成功不能替代整站验收；候选未通过就保留待验证，不宣布可替代现有入口。
- 无远程访问及外部回调需求时可标公网项不适用；公网访问、后台健康和真实定时执行各自验收，不相互替代。

## 每日批量分析验收

- 多条消息到达后已保存，约定时刻之前不触发逐消息模型调用。
- 客户指定时刻每天启动一个常规批次，按会话上下文分析；技术分组调用归属同一批次。
- 重复调度、失败补跑不重复成功单元和 CRM 写入；批次边界之后的消息进入下一日。
- 迟到、回补、编辑和撤回增量不遗漏；无增量记录空批次。
- 时区与夏令时处理、独立 CRM 提醒/超时规则的调度顺序已核实。
- 真实定时触发证据、批次 ID/游标、模型调用记录与业务回读：待填写，不能以手动触发代替。

## AI 分析尝试与报错验收

- 同一任务连续失败只发起 3 次调用（含首次），日志逐次保留次数、时间、结果、错误摘要及已知用量；第 2 次成功则不发起第 3 次。
- 格式修复及 SDK/HTTP/队列的重试共用额度；并发领取、进程中断、重启、隔日调度和补跑均不能突破上限或重复成功步骤。
- 第 3 次失败后停止自动调用并报错，CRM 待审核的“系统处理异常”区实际显示一条失败提醒；不可重试错误提前停止也能进入。核对影响范围、原因、次数和日志定位，不能只凭错误日志判通过。
- CRM 入口暂不可用时保留待投递错误，恢复后只生成一项；报错投递不触发模型重分析，其他独立单元正常继续。
- 技术失败没有业务通过/拒绝按钮；修复后在已有授权或明确补足的恢复授权内处理指定范围，恢复任务关联旧任务且仍最多尝试 3 次。原失败次数保留，未恢复不推进成功游标；恢复成功后当前提示消失，新结果按正常字段规则执行。
- 默认没有每日 token 硬上限，正常成功用量超过旧 12 万阈值不会被旧规则阻断；以配置回读及受控模拟边界验证，无需为验收消耗真实额度。生产计数、真实日志与待审核可见性另记实测证据。

## 输单与原因验收

先核对crm-fde已有期限工作流及激活版本，验证聊天事实与原流程衔接；规则未变不重复建立关单定时任务。

按企业已定规则覆盖：明确拒绝、达到不回复期限、未到期限、客户及时回复或有效推进、销售追问不等于客户回复、有普通沟通但阶段停滞、约定延期、已排除阶段、跨渠道回复及采集缺口。检查自动输单/待审核与客户策略一致，重复批次不重复结束。

验证输单主要原因固定选项、客户不回复与停滞的区分、其他兜底及证据说明；不因无回复推测价格或他供。真实回读确认阶段及原因同时保存，列表可筛选/汇总，早期商机不被原因必填阻断；重开和人工更正保留历史依据。未验证的来源或程序不能靠模拟结果宣称已上线。

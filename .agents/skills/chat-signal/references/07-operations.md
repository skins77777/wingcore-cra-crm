# 验收、成本与运维

## 验收要能解释业务结果

先在客户隔离目标使用合成或授权脱敏样本，不将真实客户记录当随意可写的测试夹具。测试前明确哪些工具会创建/修改数据；名字带 verify/test 不能证明它只读。测试数据留证，不默认批量清理。

| 层 | 核心案例 | 有效证据 |
| --- | --- | --- |
| 接入 | 入站/出站、重放、错误凭据、实例不匹配 | 来源身份、去重计数、拒绝结果 |
| 完整性 | 断线回补、晚到、编辑、撤回、缺媒体 | 缺口状态、修订依赖、待补范围 |
| 业务理解 | 同客户多采购、否定/条件句、金额修订、单位 | 标注预期、结构化结果、对应原文 |
| 写入 | 幂等新建、更新冲突、请求超时、失效租约 | 远端回读、唯一任务/映射、attempt |
| 审核 | 通过到执行、拒绝、过期计划、重复决定 | 状态/队列/远端三者一致 |
| CRM 工作流 | 赢单建单一次、统计修正、关联保护 | 真实触发、订单数/金额/客户关系 |
| 调度 | 每天一个常规分析批次、客户指定时刻与时区、夏令时、无人值守触发 | scheduled 日志 + 批次身份/游标 + 模型调用归属 + 业务结果 |
| 成员 | 允许与拒绝成员、跨账号/工作区 | 服务端结果与正常 UI 会话 |
| 恢复 | 执行器离线、数据库/会话备份恢复 | 持久任务保留、恢复后无重复副作用 |

没有启用的能力标不适用，未发生的定时窗口标待验证，不用手动触发冒充真实调度。已通过样本不是长期准确率或容量承诺。

## 接通的最终检查

逐阶段梳理后，对本次启用的阶段规则验证其已确认正例与反例，覆盖不变、更新字段和允许的转换；人工维护/待定阶段不因表格完整就启用。规则讨论、模型输出验证与真实 CRM 写入结果分别记录。

用同一会话的一组消息贯穿：持续接收并保存 → 每日批次统一读取 → 结合上下文提取事实 → 客户规则 → 精确任务 → CRM 回读 → 原生工作流。至少包含先表达意向、后确认或更正的上下文，以及一个不应写入的反例。

验证到达指定时刻前消息已保存且没有逐消息模型调用；指定时刻只启动一个常规批次，多个分组调用均归属该批次。重复调度不重复执行，失败补跑不重复已成功单元，批次上界之后的新消息留至下一日，迟到与修订不遗漏。无增量时记录空批次；上午或其他时刻的 CRM 提醒不被分析频率改写。记录环境、版本、时间、输入、预期、实测和证据引用。

当前客户与参考案例使用不同字段/阶段/时区时，应证明改配置即可生效，或者明确记录新增组件版本。测试模板里不存在真实结果，不能把填满文档当通过。

## 字段和来源验收

按本次采用范围验证客户资料补充与更正、客户生命周期和商机进度分离、原单改量与新采购、订单总额与定金、同客户多商机、联系人总览与商机小结。每项记录原值、证据、模型事实、预期变化和真实回读；无新事实不应清空已有字段。

Email 覆盖收发方向、已有身份、抄送/多收件人、重复同步、系统/推销邮件、同一回复链多采购与缺失背景；WhatsApp 覆盖双向消息和采用的修订事件。启用跨渠道综合分析时，用一边提出需求、另一边更正或确认的案例，验证关联、模型载荷和最终字段，不能仅以两个接收器健康作为通过。

采用 [连续示范](12-worked-example.md) 的方法生成本企业案例，使用本企业的预期规则，不照抄示范阶段或金额。

## 日常观测

分别看账号连接和缺口、最后收到消息、已处理游标、队列积压/最老任务、失败/冲突、模型用量、最后成功写入、规则版本。无新消息与接收器故障不能都显示“正常无更新”。

低成本来自增量、精简上下文与有界重试。同一 AI 分析任务最多尝试 3 次（含首次），逐次记录日志；耗尽或不可重试时记录终止错误并在 CRM 统一“待审核”的系统异常区提醒，保留剩余范围，不跳过消息或标成功。核对终止任务、待投递错误和当前异常提示是否对应，不能只查日志。默认没有每日 token 硬上限；客户另设预算时，耗尽也需保留剩余状态与恢复计划。客户资源账单与实施/维护费用分开。

客户报告缺少客户/商机、附件阻塞或小结失败时，按 [故障经验与回归](14-processing-lessons.md) 逐段追查，不以客户列表搜索或日志总数代替链路核对。业务待确认和系统异常分别计数；消息提醒按实际作用范围记录。

## 故障路径

VPS 的 systemd 回读命令、oneshot 正常空闲状态、备份层次与额外定时器盘点见 [VPS 部署参考](15-vps-deployment.md)。Cloudflare 仅作入口时，不通过修改其 Cron/Queues 修复 VPS 调度。

| 现象 | 先区分 | 下一步 |
| --- | --- | --- |
| 没有新消息 | WhatsApp 离线、Webhook 未发、鉴权/路由拒绝、持久化失败 | 逐段查实际事件和数据库证据，不只看 health |
| 连上了但缺历史 | 状态恢复但未回补 | 保留缺口，按数据源能力补齐/对账 |
| 定时不跑 | 调度未触发、执行器报错、时区/窗口、持久任务未推进 | VPS 按 timer → service → 数据库批次/租约核对；其他已有环境按实际调度器核对，避免反复改调度重置观察 |
| running 卡住 | 无租约回收或旧代仍写 | 查到期/generation，按实现恢复，防止双执行 |
| AI 结果错误 | 商机归属、规则版本、原文、摘要污染、结构校验 | 保存最小脱敏复现，修复后局部回归 |
| 已批准没更新 | 决策未入队、开关、Writer、目标不可达 | 按状态链查；批准不等于写入 |
| HTTP 成功没变化 | payload errors、被忽略字段、错误目标 | 读业务响应、元数据和远端版本 |
| 重复订单/统计 | 多个维护方、并发查空、重试不幂等 | 暂停相关入口，核对业务键与事件，不全库清空 |
| 人工值被覆盖 | 旧计划/缺少版本条件/未定义优先级 | 保留前后值，恢复后补并发保护 |

同一确定性错误连续两次出现就改变诊断路径，停止盲试；不影响的工作继续。瞬时故障按既有有界策略重试，数据冲突需要重校验。

## 交付与自主维护

交付客户入口、范围、下一次执行时间、已验证版本、资源归属、凭据管理位置（不是值）、恢复办法和未决项。让管理员发起一次低影响修改，例如小结运行时间或某个支持的映射，展示差异、验证不应受影响的案例，再记录版本。

后续会话根据客户档案与现场继续。Codex 会话、技能安装和基础设施日常运行分别记录，不能把智能体正在回答理解为后台已经运行。

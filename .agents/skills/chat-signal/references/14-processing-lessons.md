# 文字分析、缺失资料与审核页：故障经验及回归

依据一次真实部署排障整理为通用实施约束；下列客户与采购均用合成称呼，不携带现场凭据、号码或聊天。用于排错、修改提取/校验、审核页及恢复流程，不要求为每次日常操作重跑全部案例。企业阶段和字段仍取客户已确认规则。

## 排查客户或商机“没有踪迹”

按规范化完整电话/邮箱定位，不只搜显示名或尾号；WhatsApp JID/LID、联系人姓名与客户公司名可能不同。逐段记录事实：原消息是否接收、是否绑定正确身份、是否进入本次增量、分析是否完成、结果里有无应创建的采购、是否生成业务审核、是否入写入任务、Twenty 是否实际存在及正确关联。连接正常、总任务数或模型成功均不能单独证明客户已录入。

有客户无商机时先查是否存在符合业务规则的采购事实；没有就不凑一笔。确有事实时定位归属/提取/校验/计划/写入在哪一层中断。界面查不到也可能是名称、关联、筛选或权限，不直接补建重复客户。

## 已发生的问题与应对

| 现象 | 已发现的原因/风险 | 实施要求 |
|---|---|---|
| 不处理附件仍无法录入 | 提示已改，但证据完整性或写入门槛仍含附件阻塞，旧任务未恢复 | 将纯文字范围贯穿采集、载荷、校验、规划与界面；核对旧任务后局部恢复，不能仅隐藏错误 |
| 多个客户统一显示“商机小结失败” | 必须覆盖的采购锚点、允许引用的本次消息/revision未明确提供或与校验口径不一致 | 程序推导 required summaries 与允许证据，显式传入；错误分别指出缺失、多余、错误锚点、引用越界；不能关闭校验硬过 |
| 数量校验失败或变小 | `50,000` 被解析成 `50`，完整 token 边界错误 | 正确处理千位分隔、空格、小数、符号和单位，不接受局部匹配、无依据求和或负数变正数 |
| 地址写入持续冲突 | 编码/合并两次时，不变的 null 或有限数值经纬度被当异常 | 同值合并保持稳定，地址子字段保留；真实国家/城市冲突继续保护，不全局放宽覆盖 |
| 审核仍是失败日志 | 技术错误被套成业务审核，客户无可回答的问题或按钮 | 独立系统异常区负责告知与排查；业务卡片必须给出具体问题、证据、选项和提交动作 |
| 商机归属不明却无审核内容 | 只保存异常码，没有持久提案；或纯寒暄被误报 | 有实质采购歧义才生成候选与可执行选择；无新事实允许 no-change |
| 改完代码后定时服务失败 | 类型检查通过，但目标 Node 的 TS strip-only 不支持构造器参数属性 | 核实实际运行方式，用目标运行时导入/执行验证；需要时显式声明字段并赋值 |
| 恢复成功却产生重复或覆盖 | 全工作区补跑、乱序分析、复用过期计划、局部事件重建全量小结 | 按具体分析单元和写入任务白名单恢复、按业务顺序处理；回读唯一客户/采购、保留完整总览和人工新值 |

精确错误留在私有运维记录，面向客户展示影响和下一步。不能把未经确认的疑似原因写成根因，也不能用提高 token 限额或重复请求代替定位输出截断、契约错误与来源缺失。

## 有范围的诊断与恢复

1. 保留当前任务状态、版本、失败记录及必要的配置/数据备份。查明原服务是否仍在运行，用现有锁/租约避免同时修改；不为演练重启其他客户服务。
2. 先复用已保存结果或做隔离复现。仅修复 writer 的问题优先重放原写入任务；模型重分析只覆盖必须重算的失败部分。
3. 需要外部模型复现时沿用已获授权的数据范围与供应商；诊断请求/响应留在客户私有目录，排除凭据，通用技能和夹具只用合成案例。既有明确授权无需重复询问，新增数据或目的另行判断。
4. 恢复范围使用明确任务 ID/业务对象白名单；空白名单不得变成全部。保留原尝试与失败历史，恢复次数有界，确定性错误再次出现就改变诊断路径。相同客户的历史和最新批次按时间顺序处理。
5. 执行时仍校验当前远端版本。时间戳统一格式/精度后比较，不能将等价表示当冲突，也不能因此跳过并发保护。人工允许替换地址等字段时，校验后端已保存决定、任务、目标与精确字段值，不能相信请求里自行携带的“已批准”标记。
6. 逐客户回读客户、联系人、商机关系、最新小结/字段和最终写入状态；确认无重复、未覆盖人工新值、仅相关异常退出列表。最后核实实际服务和下一次调度，不把一次手工恢复当成无人值守成功。

## 布局与消息提醒

布局以 [待审核应用](13-review-app.md) 为准：顶部独立系统异常提示，主体业务确认卡片，历史显示决定与执行状态。异常提示只承担告知与排查，不强制客户批准报错；真正的业务歧义必须有可答的选项。

记录所用 Twenty/SDK 版本和实测能力。页面刷新、页面弹出提示、侧栏计数、全局铃铛分别记录；没有测过页面离开后的行为就不能声称全局提醒已上线。复制排查信息只是交接材料，未自动发送给 Codex。恢复成功的失败不再占当前提醒，历史审计仍保留。

## 按改动选取的回归案例

| 合成案例 | 应观察到的结果 |
|---|---|
| 文本姓名/需求 + 未下载 PDF，纯文字模式 | 已有充分证据的字段/采购继续；不读 PDF、不因文件阻断、不生成附件审核 |
| 仅附件增量；文本未写金额 | 不调用模型凑事件；金额保持未知，附件不伪装为识别成功 |
| 正文截断/渠道回补缺口 + 纯文字模式 | 真正文字缺口仍被发现，不能与附件一并关闭保护 |
| 两笔采购各有当前证据，其中一笔漏小结或串引用 | 精确报覆盖/引用错误，失败不冒充业务审核，也不写错采购 |
| `50,000`、`50 000`、`1,250.50`、`+50`、`-50`及不支持的数字格式 | 支持的格式按完整值和语义解析；局部 token、错误符号/单位/无依据合计被拒绝，歧义格式不猜 |
| 只有“谢谢”或补充城市 | 可保持商机不变或更新独立地址，不强制新商机或归属审核 |
| 实质采购可属于两笔旧商机 | 有具体候选、聊天依据、保持/选择及提交动作；选择后只更新所选范围 |
| 姓名明确、阶段不确定 | 姓名照常处理，阶段保持并生成具体问题；确认后才执行阶段变更 |
| 自动重试、最终失败、CRM写入冲突、已成功任务并存 | 异常区状态与真实任务一致；成功不再提醒，分析未产提案也可见 |
| 附件 + 真正技术原因的混合阻塞 | 排除停用附件提示但保留未解决技术原因，不把整项当附件过滤 |
| 旧值未变的含经纬度地址；人工已改国家/城市 | 前者可稳定编码，后者产生精确冲突/重提问题，不能无授权覆盖 |
| 相同决定重复提交、相反决定、旧摘要或伪造已批准标记 | 幂等或拒绝；目标变化后旧批准失效，生成新问题；只有回读成功才记执行成功 |
| 限定失败单元恢复；写入任务白名单为空 | 不重跑已成功单元、不新建重复采购；空白名单无任何写入 |
| 异常/审核接口读取失败、跨工作区、无权限成员 | 不显示虚假的零待办，不泄露记录；仅服务端授权成员可查看/决定 |
| 新事项在页面打开、历史页、离开页面后产生 | 按实际支持范围提示，重复轮询不刷屏；未实现的全局通知明确列缺口 |

使用 [验收模板](../assets/acceptance.md) 保存输入、预期、实测和证据；未执行的案例保持待验证。本轮参考现场的测试通过不代表分发包源码或每个客户环境已经通过。

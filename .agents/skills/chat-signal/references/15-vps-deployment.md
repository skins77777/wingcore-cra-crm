# VPS 部署参考与现场核对

仅在客户选择 VPS 版或核查已有 VPS 时读取。本页补充 [部署指导](02-deployment.md) 的具体检查方法，不修改本地版说明。先复用客户现有源码和服务；这里的名称与实现是参考，不要求重命名或另建同等服务。

## 参考实现怎样运行

| 职责 | 一种已核查的 VPS 实现 | 实施时需要确认 |
| --- | --- | --- |
| Twenty | Compose 的 server、worker、PostgreSQL、Redis、附件卷 | 应用与数据库版本、持久化、内部 API 与公网地址 |
| 接收和审核 API | Node 常驻服务，由 systemd 管理 | 开机启动、监听范围、密钥鉴权、成员与工作区归属 |
| 自动化数据与任务 | VPS 独立 PostgreSQL 保存证据、批次、租约、审核、Outbox | 最小权限、幂等、失败状态和恢复；无需另购云队列 |
| 调度与执行 | systemd timer 在上一轮结束后约一分钟唤起 oneshot 执行器 | 日批时刻由工作区配置控制；分钟轮次推进任务和恢复，不全量重分析 |
| 模型 | VPS 执行器调用外部模型 API | 真实请求、重试和超时边界、费用与规则版本 |
| 公网入口 | HTTPS 网关或反向代理，可配合私有隧道 | 只接入页面/API/回调，不执行另一套业务分析或写入 |

VPS 进程复用名为 edge、Worker 或 Hyperdrive 的代码目录/接口，不等于运行依赖这些云服务。判断依赖时看实际启动命令、调用位置、连接目标和部署资源，不能仅凭标识名称新建云端后台。

### 区分新装、迁移和恢复

- 新装：准备新数据库、卷和新凭据，执行对应版本初始化/迁移。已有实例参考配置若关闭自动数据库迁移或引用 external 卷，不能照抄到空环境。
- 迁移/恢复：使用与数据匹配的加密密钥、数据库角色、附件及配置；先验证隔离恢复，再按授权切换。不要为恢复生成新密钥，也不要把旧客户密钥用于新客户。
- Twenty 内置 Cron 的开关按已有工作流决定。参考实例使用自建调度且关闭 Twenty Cron 注册，不表示所有新客户都应关闭其已有确定性定时工作流；同一职责保持唯一执行者。
- 固定实际应用、数据库与运行时版本，记录镜像摘要。源配置只有标签时不能当作已锁定不可变产物；不要在一次核查中顺便升级生产服务。

### 网络与持久化

宿主机进程可用回环地址访问数据库，容器内须用该容器网络可达的地址；不能把宿主机 localhost 复制到容器当成同一数据库。自动化库与 Twenty 库保持明确身份，若桥接两套 Compose 网络，使用不与既有数据库冲突的专用别名，并将网络连接声明或重建后的恢复步骤写入部署记录。

核对 API 监听地址、端口发布、数据库角色权限、附件卷与备份位置。数据库与 Redis 不开放公网。公网入口切换应同步 Twenty 对外地址、服务间 API 和实际采用的回调地址，内部消息投递无须绕公网。

## 调度排错与只读回读

采用 systemd 的 VPS，按“timer → service 最近结果 → 工作区时区与日批窗口 → 数据库批次/租约 → 模型和写入结果”检查。使用客户实际单元名；常见只读命令示例：

```sh
systemctl show crm-automation.service --property=ActiveState,SubState,Result
systemctl show crm-automation-run.timer --property=ActiveState,SubState,LastTriggerUSec
systemctl show crm-automation-run.service --property=Result,ExecMainStatus
journalctl -u crm-automation-run.service -n 80 --no-pager
```

oneshot 执行器结束后 inactive/dead、timer active/waiting 可以是正常状态；结合最近退出结果和触发记录判断，不直接重启或重放任务。窗口与批次查询采用只读事务，避免为排错手工运行会触发模型或真实写入的执行器。日志仅在私有环境检查，输出前移除业务正文与秘密值。

每日一个分析批次与分钟执行器不冲突。具体批次时刻、时区、AI 重试上限、写入重试、批次恢复边界分别记录；不能把切换时刻后的追赶处理误认为另起一个日批。未采用 Cloudflare Cron/Queues 的 VPS 不用修改这些资源排错。

## 地址同步交接：由 crm-fde 负责

关联客户地址到商机客户地址的同步是 VPS 标准基建，由 crm-fde 部署、启用与验收，具体见 [确定性规则与工作流](../../crm-fde/references/twenty/05-workflows.md)。当前参考实例由 VPS 独立定时脚本调用 Twenty API 实现，不依赖聊天或模型；运行进程的位置不改变职责归属。

chat-signal 读取基建交付的来源/目标字段、关联、唯一执行者和验证记录，复用该能力。聊天识别仅按客户规则维护来源地址事实，不再部署同步定时器，也不直接竞争写入商机客户地址镜像。语义不同的收货地址另按已确认映射处理。

缺少 crm-fde Skill 时读取等价基建记录，仍按同一职责核对；同步或字段未就绪则登记基建待补齐，不能标记为聊天接入的可选功能或已经完成。接入后的联调只验证来源更新能沿已有同步链传播，并确认没有第二个维护者。

## 其他扩展与备份差距

同时盘点主执行器、标准地址同步之外的定时器、Twenty 工作流和脚本，登记各字段唯一维护者与锁/幂等保护。其他客户扩展按其已确认规则适配，不直接复制作者工作区或字段 ID。

区分同机备份、异机备份与恢复演练。同机快照成功不能证明主机丢失后可恢复；核查传输目标、最近成功传输与隔离恢复证据。只有同机方案时保留这一事实，把异机能力标待落实，不降低要求或宣称已有。备份可能含数据库、附件和私有配置，不得纳入脱敏参考包。

没有客户选择的备份目标、访问配置或相关实施授权时，可以完成现状核查和配置差距记录，不擅自上传客户备份到其他服务。是否实施生产变更按当前任务范围决定。

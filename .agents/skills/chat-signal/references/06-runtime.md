# 获取、适配和维护运行组件

## 本 Skill 的交付边界

运行本 Skill 不需要作者原项目，但要实现持续自动化，必须有客户可使用的运行源码/发布产物或新建的等价实现。本包包含知识、模板、两个本地档案工具和 [待审核应用源码](../assets/twenty-approval/README.md)；该应用提供 Twenty 页面和服务端代理，后台持久审核、业务规则与执行仍要在客户环境适配。

先查客户项目、明确提供的代码仓库和已部署服务。拿不到运行组件时完成蓝图交接、字段盘点、能力差距与可实施方案；说明待实现部分，不虚构下载地址或临时切换到作者线上服务。用户已授权实施且需要补代码时，在客户项目内按有界范围实现和测试，不能止于“缺组件”而放弃其他可完成工作。

## 选择可运行的最小方案

优先顺序：客户现有组件 → 可获取的受维护发布产物 → 客户项目内的必要适配或最小后台。逐项记录来源/许可、版本、安装命令、配置入口、启动与健康检查、数据位置、备份和升级方法。以真实安装和业务结果证明可用，不以交接 JSON 代替后台。

先沿用 [部署指导](02-deployment.md) 中的 VPS/本地选择。VPS 版的业务数据、接收、队列、调度、分析编排、审核与写入在 VPS 运行，公网平台只做接入；不得因参考代码使用 Worker/Neon 就重建旧混合云链路。本地版核对实际依赖及运行位置，旧环境迁移单独记录范围，不擅自停用既有服务。

不把本地候选模拟、通用规则引擎或归档发布器作为部署前置。待审核入口作为客户能力保留，按已确认规则接通随包应用或已有等价入口。Twenty 已负责的统计和提醒继续由它负责；只为实际缺口添加程序。开发在客户明确需要的范围内进行，不把一次部署演变为通用平台开发。

## 参考组件分层

| 层 | 可复用职责 | 客户变量 |
| --- | --- | --- |
| connectors | 供应商事件标准化、修订、身份提取 | 实例、事件订阅、账号绑定 |
| persistence | 证据、游标、记忆、映射、Outbox 与 audit | 数据库身份、角色、版本 |
| ai | 路由、结构化提取、上下文选择、校验 | 模型服务、规则、用量预算 |
| domain | 事实投影、阶段/金额/字段策略 | 业务含义、分支、单位、时区 |
| crm | 映射、编码、并发保护、dispatcher | 目标字段、枚举、对象关系 |
| 后台进程 / apps | 接收、调度、持久任务、审核与状态 | 所选 VPS/本地运行位置、服务资源、Secret、权限 |

它们是逻辑职责，不要求每层一个服务或仓库。保持必要边界，同时减少部署复杂度。

## 原型到客户版的核对项

1. 去掉隐式回退到旧地址、账号、测试工作区、公司分类、固定汇率和本地路径；所有目标显式注入。
2. 将仅允许测试前缀的限制换成正式的客户登记、身份、权限和模式检查，不能简单删除防护。
3. 区分单账号实现与多账号服务；扩展后验证跨账号查询、路由和同客户关联。
4. 检查硬编码阶段/单位/事件枚举/星级规则。配置文件写得出来不等于验证器和投影器支持。
5. 核对模型输出、候选、自动入队、新建与关联、审核决定和执行器是否完整连接，分别验证状态。
6. 各组件明确读取同一客户规则/映射版本；恢复与重试保留原任务快照。
7. 固定依赖、迁移、构建与镜像版本，记录可实际运行的命令与目标环境；不能直接用随时变化的 latest。

## 改造方式

可表达的差异用配置；缺少一种业务能力时补适配器/规则算子并加入通用回归，不默默为每个客户复制核心分支。保留客户扩展及其版本和测试证据。暂不能支持的规则在对应功能处显示受阻，不篡改客户定义迁就实现。

高风险重复逻辑优先工具化：读取元数据、验证引用、金额编码、迁移状态、幂等入队、回读。智能体负责选路径和解释差异，脚本/API 负责可重复动作。可以先使用已支持 CLI/API，必要时再统一为 MCP；技能不能假定每位客户都有作者的连接器。

## 发布与回退

在客户档案保存源码/产物引用、版本、校验和、部署资源、数据库迁移、规则和映射版本。升级前查看真实差异，按运行端兼容性验证。旧实例恢复和新装分开，不能为新装沿用旧加密密钥。

回退代码不能自动回退数据库、撤销已经发送的消息或抹掉已生成的业务记录。选向后兼容迁移或明确补偿流程；不要以重建卷、清空数据库或批量删除资源作为默认修复。

## 能力矩阵

按“需求 → 对应组件/版本 → 已实测/仅文档支持/缺失 → 样例和证据”登记。独立的客户配置包通过静态检查只是准备联调；真实能力来自目标环境的行为证据。

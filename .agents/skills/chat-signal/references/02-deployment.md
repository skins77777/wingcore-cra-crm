# 环境、部署与资源归属

## 先读现场

列出当前可用工具、运行组件来源/版本、目标账号与工作区。CLI 已安装不等于已登录，已登录不等于指向客户环境。先调用只读身份/健康/元数据接口；日志仅保存身份摘要，不输出密钥。

先复用客户已有环境与部署选择。客户自己持有账号与数据，实施者通过可撤销授权工作；不得将旧客户分支或数据库复制给新客户。

## 只区分 VPS 版和本地版

| 版本 | 运行职责 | 部署前核对 |
| --- | --- | --- |
| VPS 版 | Twenty、消息接收、业务数据库、队列、任务调度、分析编排、审核后台与 CRM 写入统一运行在 VPS；模型调用外部 API | 以 2 核 4 GB Linux 为起点，核对版本、持久化、服务与实际负载 |
| 本地版 | Twenty 与本次安装的自动化后台运行在客户电脑，模型默认调用外部 API | 核实已有组件与依赖的实际位置、Docker/进程状态、休眠关机影响与恢复方式；不把 VPS 或历史混合云结论当成本地实测 |

公网入口是版本内的访问配置，不是另一个运行版本。**VPS 版中 Cloudflare 仅承担域名、HTTPS、请求转发或隧道等公网接入职责，不承担业务队列、定时分析、业务数据存储或 CRM 写入。** 即使入口用 Worker，也只作为网关；不引导客户另选 Workers、Queues、Cron、Neon 或 Hyperdrive 搭建业务后台。

旧记录中的 Cloudflare 分析链、Neon 存储和本地加云端执行器仅供历史排错。接管时先盘点实际运行位置；发现旧混合部署，记录差异、依赖和迁移范围，不直接关停、删除或自动恢复旧组件。客户已有部署未完成迁移时，说明其真实状态，不虚称已符合 VPS 版。选本地版也不能承诺电脑关闭后仍持续接收或分析。

## 组件按所选版本落地

| 服务 | 职责 | 部署前核对 |
| --- | --- | --- |
| Evolution | 持续连接授权 WhatsApp 业务账号、推送事件 | 固定镜像版本、激活/许可要求、数据库、Redis、会话保存、HTTPS |
| 自动化后台 | Webhook 接收、持久任务、调度、分析编排、审核与写入 | VPS 版在 VPS 运行；本地版核对本机后台与实际依赖；服务版本、配置引用、唯一执行者 |
| 业务数据库 | 业务证据、配置、实体映射、任务与审计 | VPS 版在 VPS 持久化；本地版核对本机持久化与已有依赖；数据库身份、权限、备份恢复 |
| 公网入口（按需） | HTTPS、页面/API/回调请求转发 | 可达源站、鉴权、域名与路径、协议支持；不承担业务分析和写入 |
| Twenty | CRM、原生工作流、统一待审核入口（随包 App 或已有等价入口） | 所选部署位置、API/App 能力、字段/权限、内部与对外地址 |
| 模型 API | 对话事实与小结提取 | 所选模型及结构化输出、超时、预算、数据范围 |

按客户采用的功能选择相关组件，不把整张表当采购清单；各行是职责，不要求分别购买或新建服务。模型 API 是外部调用，分析编排仍在所选运行环境。已有 Twenty 实例先核实并复用，不能为符合版本标签擅自迁移客户数据。

## 公网 HTTPS 入口的选择

仅本机使用且无外部回调需求时跳过。远程访问或渠道需要 Webhook/OAuth 回调时，先复用已有稳定入口，让客户选择已有资源或偏好，技术可行性由 AI 核实。可明确列出：

| 方案 | 怎样连接客户服务 | 使用条件 |
| --- | --- | --- |
| 自有域名 | DNS 指向 VPS，由 VPS 上的反向代理提供 HTTPS；本地部署可配合隧道 | 域名本身不运行服务；核对证书、源站和访问规则 |
| Cloudflare | 域名代理，或通过网关与 Tunnel 连接 VPS/本地服务 | 按实际方案核对自有域名或平台地址是否可用；临时 Tunnel 地址仅用于测试，长期入口需稳定 |
| Vercel | 平台项目网址通过外部 rewrite/反向代理转发到 VPS | 平台必须能访问源站；按当前官方限制验证登录、上传、SSE/WebSocket 等实际所需能力；不能直接连接客户的 localhost |
| GPT 站点（ChatGPT Sites） | 托管站点连接 VPS API，或在能力允许时转发服务 | 候选方案；先核实外部连接、身份认证及完整代理能力。仅 API 成功不等于 Twenty 整站可用，不为取得网址另建 CRM 前端 |

这些方案解决同一个公网访问需求，但配置方式和能力不同，不保证无条件互换。使用托管转发时，路线是“客户访问平台网址 → 平台转发 → VPS 服务”，Twenty 和业务后台仍在 VPS。替换现有入口前核对新平台能否到达源站；旧 Cloudflare 私有隧道不能自动被 Vercel 或 GPT 站点复用。

配置及验收：

1. 记录最终浏览器入口、Twenty `SERVER_URL`、服务间地址和实际采用的回调地址；同 VPS 内的消息投递优先走受控内部网络，无需绕公网。
2. 保留 Twenty 登录与 API/回调鉴权，核对 Host、转发头、Cookie、重定向和所需连接协议。密钥留服务端；CRM 私密响应不做公共缓存，不公开数据库或 Redis。
3. 从实际外部网络验证登录、刷新、数据保存、附件上传下载及采用的实时连接；回调另验签名/认证和事件接收，不能只看首页或 HTTP 200。
4. 换入口时同步相关地址并保留恢复方式；完成新入口验证后按授权切换。只改变访问路径，不另起分析调度或写入器；记录限制与未通过项。

本地公网入口不会让关机电脑保持服务；DeepSeek 等出站 API 调用本身不要求公网域名。公网入口验收与业务后台、真实定时任务验收分开记录。

## VPS 的具体实施参考

选择 VPS 版后读取 [VPS 部署参考与现场核对](15-vps-deployment.md)，补齐运行产物、新装与恢复、容器网络、systemd 调度、标准地址同步和其他扩展的具体检查。脱敏参考包是实施参照，逐文件在线核对不等于完整后台或空机安装已经通过；不要直接照搬已有实例的迁移开关或固定字段身份。关联客户地址同步到商机是每家 VPS 客户的标准基建，由 crm-fde 按客户实际字段映射部署并验收；chat-signal 核对交接结果，缺失时登记基建待补项，不另建重复同步。

## 演进部署步骤

1. 读取确认配置与源码，生成资源计划和能力差距；对已有配置导出备份。
2. 固定版本与校验和，准备同客户的隔离验收环境与恢复点。数据库变更验证后再按既有授权应用，不默认购买云数据库分支。
3. 建数据表和索引、最小权限服务身份、应用配置；迁移可重复检查，不覆盖旧业务记录。
4. 在选定版本的运行环境部署接收器、持久任务、调度、分析服务与写入器，分别绑定 Secret。公网网关只转发请求；所有组件核对同一逻辑工作区，清除旧实例默认回退。
5. 连接 Evolution 事件，验证入站和业务员发出的消息都正确归属；按版本读取真实 payload，不凭事件名称猜结构。
6. 核验 Twenty API 及可选 App、成员身份；再启用约定范围的调度和写入。
7. 记录资源 ID、配置摘要、完成步骤、故障和恢复点，以便断点续接。

后台已更新 Webhook Secret、Twenty App 中仍是旧 Token，或 URL 正确而逻辑工作区错误，都会造成部分链路失败。逐段核对网关、后台与应用的真实配置；不要通过换成管理员通用凭据掩盖路由错误。

## 网络与执行位置

调用者与 Twenty 在同一 VPS 或容器网络时使用该网络内可达地址。Twenty 在本地/私有网络且调用者在外部时，需可达的受保护连接；`localhost` 和 `http://server:3000` 只在相应网络空间有意义。已有托管 Twenty 作为接管现状记录，不扩展出第三种 CRA 后台版本。

同一任务只由约定执行者处理。VPS 版在 VPS 调度，本地版核对本机调度与实际依赖；Twenty 的确定性工作流各自负责其业务，不能重复消费同一任务。保留租约与幂等，记录开机/休眠造成的延迟和恢复行为，不宣称电脑关机仍会写入。

## VPS 起步规格

整套 VPS 版以 2 vCPU/4GB Linux 为起点，按实际安装的 Twenty、消息后台、数据库、Redis 和渠道连接器合计测量资源，模型调用外部 API；不能把只运行 Evolution 的历史容量经验当作整套容量保证。磁盘按消息、附件、日志和备份增长核算；多号、媒体或历史同步较重时先实测瓶颈，减少不必要组件与峰值并发，不默认升配。这不是账号数量保证或官方最低规格。

选择支持版本的 Linux 与镜像架构、稳定网络、可扩容磁盘和异机备份。数据库/Redis 不直接向公网开放。监测峰值内存、OOM、CPU、磁盘、连接、Webhook 积压，按实际瓶颈扩容。备份数据库及该版本实际保存的会话/实例数据，演练恢复。

取得公网网址不会自动启动 Evolution 或业务后台。API/Redis/数据库版本、官方或 Baileys 接入路线、激活条件和许可证在安装时重新查证。固定版本不等于永不升级，升级先回归再切换。

模型 API 的实际接通步骤见 [模型配置](09-model-setup.md)。客户选定部署路线后，在客户实施记录写出该版本的安装、配置、启动、备份和回读命令；不能只交付本页的抽象服务表。

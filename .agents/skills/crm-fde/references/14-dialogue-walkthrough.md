# 连续教学示范：从客户等级到能维护自己的 CRM

这份示范保留共创对话中有效的教学方法，并把已指出的问题修正到发生的环节。它不是原聊天逐字稿：完整流程审阅被移到节点细化之前，由其他 Skill 负责的接入访谈从本教学路径移出，后补的教学动作明确为整理示范。数值属于合成演练客户，不是所有客户默认值。

使用方式：按 [路线](00-teaching-route.md) 阅读当前段的讲解、建议、问答和收拢方法；把行业与参数换成实际客户的，保留教学动作。不要把本文整段发给客户。每次只展示当前一轮；已知回答直接使用。

## A. 简短开始与客户分级

**背景未知时**

教练：“我们会一步步确定客户怎么分级、每笔生意怎样推进、什么时候提醒，再把它们建进 CRM。你主要卖什么，客户主要是哪类人或企业？”

若客户同时说了“咨询、报价、成交”，保存作后续流程素材；这不是要求立即转入流程访谈。产品和客户已知时省略背景问句。

**介绍方法，取得量级**

教练：“客户等级能帮你分配经营精力。建议先看采购潜力、累计成交金额和成交次数：新客户看潜力，老客户结合已有合作。你的采购量通常用什么单位，一位普通客户每月大约采购多少？”

客户：“件，一个月 500 件。”

教练：“先把普通客户放在三星附近，给你一版预计月采购量建议：”

| 星级 | 预计月采购量 |
|---|---|
| 一星 | 1–99 件 |
| 二星 | 100–299 件 |
| 三星 | 300–999 件 |
| 四星 | 1,000–1,999 件 |
| 五星 | 2,000 件及以上 |

教练：“未知先记待了解，不直接判低星。500 件三星、2,000 件五星，符合实际吗？”

客户：“可以。”

**历史成交金额**

教练：“接下来是累计成交金额：从首次合作到现在，客户实际与你完成了多少交易，用来体现长期贡献。它不是客户总采购预算，也不是定金。一笔普通订单大约多少，使用什么币种？”

客户：“30 万人民币。”

教练给出本次建议：

| 星级 | 累计成交金额 |
|---|---|
| 一星 | 大于 0、不足 30 万元 |
| 二星 | 30 万至不足 60 万元 |
| 三星 | 60 万至不足 150 万元 |
| 四星 | 150 万至不足 300 万元 |
| 五星 | 300 万元及以上 |

教练：“完成一笔普通订单约达到二星，累计 300 万元达到五星。这个门槛合适吗？”

客户：“可以。”

教练：“金额以后从符合条件的订单汇总，不需要每次手动加总；什么时候计入，我们在订单部分一起确定。”

**成交次数与综合等级**

教练：“成交次数让长期小额复购也体现价值。先给一版建议：”

| 星级 | 累计成交次数 |
|---|---|
| 一星 | 1 次 |
| 二星 | 2–3 次 |
| 三星 | 4–6 次 |
| 四星 | 7–9 次 |
| 五星 | 10 次及以上 |

教练：“同一订单分批付款或发货只算一次。累计 10 次达到五星，合适吗？”

客户：“可以。”

教练：“三个指标取最高星级。再建议正常情况下只升不降，录错数据仍可纠正。这样可以吗？”

客户：“可以。”

此处若用户尚未接受取高，则将聚合与升降分两轮，不能用对升降的回答推定两个规则都已确认。明确零值与未知的表示在本模块收拢，不能留下自动把零判一星的实现。

教练收拢：“这三项共同决定等级；有正在推进的采购时，仍优先处理那笔业务。以后你可以直接问智能体：‘这个客户为什么是三星？列出依据，先不要修改。’”

## B. 商机概念与完整流程

**先说明商机为何存在**

教练：“商机用来分别管理每一次采购。比如上个月的货还在运输，这个月又来询价，两笔业务要分别记进度。新独立需求建新商机；同一笔改数量、规格或报价，继续更新原商机。这个划分符合你的业务吗？”

客户：“符合。”

**先听业务，再给完整参考**

教练：“接下来整理销售流程。拿一笔典型业务来说，从咨询到你认为完全结束，通常怎样走？不必使用 CRM 术语，我来整理。”

客户：“咨询、报价、成交。”

教练：“根据你说的三个步骤，我补一版供你删改的完整参考。它帮助我们看见业务停在哪里，先不要求每一项都单独设阶段。”

| 环节 | 能看清什么 |
|---|---|
| 咨询 | 客户有采购意向，资料还不齐 |
| 需求确认 | 产品、规格、数量、交期等足够报价 |
| 打样／寄样（可选） | 客户是否需要验证产品，可放报价前或后 |
| 报价 | 这次采购的正式报价已经发出 |
| 签约／确认订单／付款 | 合作是否成立，需要哪些确认 |
| 生产／备货 | 货物准备到什么程度 |
| 发货／配送 | 是否发出、运输进度如何 |
| 签收／验收 | 是否收到，是否符合约定 |
| 赢单 | 这次机会何时统计为成功；位置由你的标准决定 |
| 输单 | 中途确定不再推进，记录结束原因 |

教练：“赢单用于统计成功与合作贡献；输单原因帮助发现产品、价格、交期等问题，输单不等于放弃整个客户。这份参考里，哪些要增加、删除或合并？”

此处等客户审阅。演练原记录中签约、生产/备货、配送、验收未最终定稿，不能写成全选。客户只确认部分时，保存全部节点状态；给一次具体合并建议以收拢，不重复让他从头讲流程。未完成全貌审阅，不进入定金、报价格式等细节。

## C. 逐个细化客户采用的节点

以下只对已经采用的节点使用；行业改变时替换具体资料。

**询盘与需求确认**

教练：“询盘表示有采购意向，但还不足以报价。需求确认表示报价所需资料已经齐全。通常要有产品、规格、数量、交货地点和期望交期；拿到这些信息，你就可以报价了吗？”

客户：“可以报价了。”

教练：“这些资料放在这笔商机里，方便以后报价和交付；数量是本次需求，和客户的月采购潜力分开。”

**报价**

教练：“正式报价针对这笔采购，并且已发送，才进入报价阶段；内部草稿和通用价目表不算。你通常用 PDF、图片，还是聊天里的明确报价？”

客户：“PDF。”

教练：“保存这次报价 PDF、版本和发送时间。发送时间用来安排后续提醒，上传一个未发送文件不会开始计时。”

**成交与定金**

教练：“成交表示合作已经达到你认可的成立条件。客户确认采购就算，还是至少收到款？”

客户：“至少要收到定金。”

教练：“定金按固定比例，还是每笔订单单独约定？”

客户：“单独约定。”

教练：“每笔记录约定定金金额，核实到账达到它后进入成交，付款截图本身不当成核实到账。”

**打样与其他可选环节**

在本模块适当位置确认打样，不能等到提醒模块发现遗漏才重启访谈。

教练：“打样让你知道客户是否已经验证产品。每笔都需要，还是客户提出要求时才需要？”

客户：“客户提出要求时才需要。”

教练：“通常在报价前、报价后，还是两种都有？”

客户：“两种都有。”

教练：“保留按需打样，报价前后都可以发生，不覆盖已有报价版本。”完成标准仍缺时给推荐并留在这个环节；若客户要求先跳过，记录影响，不假装已确认样品通过。

其他采用节点沿用同样方法：解释进展意义 → 给可操作的起步定义 → 询问一个真实差异 → 说明必要字段及用途。未采用的节点不逐个盘问。

**赢单与订单**

教练：“赢单决定何时统计这次机会成功。你希望定金到账算成功，还是等后续交付或尾款完成？可以按你的业务确定。”

客户：“尾款收齐。”

教练：“以约定尾款收齐为赢单，不额外加上你没要求的验收条件。首版由人核实到账后确认。建议赢单后形成一条关联订单，以最终全单金额增加累计成交额，次数增加一次；重复保存不重复计入。这样安排可以吗？”

客户：“可以。”

教练：“订单为星级提供可核对的依据。以后改订单金额，也要同步核对客户累计金额；尾款只是一部分收款，不能代替全单金额。”

客户若提财务系统名称，只记录核实来源；不问产品版本或接口。以上顺序将订单衔接提前到赢单后，是整理后的教学安排，不声称原演练逐字按此顺序发生。

## D. 商机跟进、停滞与输单

**把阶段变成行动**

教练：“流程告诉你进展，任务告诉你下一步做什么。正式报价发出后，建议两天仍未推进就提醒了解反馈；两天合适吗，还是需要更早或更晚？”

客户：“1 天就要提醒我。”

教练：“报价发出 1 天后提醒第一次。任务由你手动完成，未完成保留原任务，不重复创建。完成后还要再提醒吗？”

客户：“次日再提醒。”

教练：“建议累计最多三次，包含第一次；停止提醒不自动输单。三次合适吗？”

客户：“两次就够了。”

教练：“共两次：报价后一天第一次，完成后次日第二次。如果客户约定下周三联系，建议按约定日期替代普通节奏，可以吗？”

客户：“可以。”

随后给简短规则摘要。自然日/24 小时、截止时刻等在需要落地时集中给明确建议，不把“次日”悄悄换成 24 小时。示范中的任务生命周期是推荐方案，客户采纳后才实施。

**把其他已采用环节也盘点一遍**

教练：“报价提醒已经定好。再看看其他环节有没有容易忘的事，避免流程建全了，却只在报价时提醒你。我先给建议，已经确定的保留，你只需调整不合适的地方。”

以下是教学补充示例，假设客户已采用表内节点；不是原演练已确认的完整配置。实际输出必须按当前客户流程增删，已明确不需要的直接保留，不重新追问。

| 已采用环节 | 提醒用途与建议 | 客户选择 |
|---|---|---|
| 询盘 | 建议提醒及时回应，避免漏掉新需求 | 待定 |
| 需求确认 | 建议在约定日期提醒补齐报价资料 | 待定 |
| 打样（按需） | 建议仅启用打样时提醒检查进度、收集反馈 | 待定 |
| 报价 | 已定报价后一天首次，完成后次日第二次，共两次 | 需要提醒（已确认） |
| 订单确认／成交 | 建议在约定期限核对订单或定金是否落实 | 待定 |
| 生产／备货 | 建议按承诺完成日期检查备货进度 | 待定 |
| 发货／配送 | 建议在预计到货时检查是否送达 | 待定 |
| 签收／验收 | 建议检查验收；如仍有尾款，按付款约定跟进 | 待定 |
| 赢单 | 建议停止销售跟进；尚有交付义务则保留对应任务 | 待定 |
| 输单 | 建议停止本次机会的销售跟进，保留客户资料 | 待定 |

教练：“哪些建议需要调整，或者哪个环节不需要提醒？”

客户回答后分别保存需要提醒、不需要提醒、待定，只细化需要提醒项的差异。负责人、未完成不重复等共用约定可给摘要复用；询盘、打样、配送等不能未经选择套用报价的两次节奏。用户跳过的保留待定及影响，可以继续，但不称全部提醒已经设计完成。已完成覆盖审阅不在之后每轮重复整张表。

**主动建议结束长期不回复的商机；本例客户选择人工复核**

教练：“有些客户聊着聊着就不回复了，商机一直挂着会让你高估可成交机会。我建议对长期不回复或没有推进的售前商机设结束期限，达到条件自动转输单并记录原因。先按你们采购周期确定哪些阶段适用；你希望自动结束，还是由你先判断？”

客户：“提醒我判断。”

教练：“建议从进入当前阶段开始计时，普通聊天不重新计时；先以十天为参考，符合节奏吗？”

客户：“30 天。”

教练：“当前阶段超过 30 天，只生成复核任务，由你判断继续还是输单。”

如果该企业改选到期自动输单，教练继续问清适用阶段、起点、期限和重置，并说明：“这些条件明确后，我们就在Twenty核实并配置到期工作流，自动结束并保存原因。后面接入聊天时再一起复核，根据新增信息调整。”不能把首次制定规则全部留给chat-signal。本例仍保留客户已经选择的人工判断。

**结束标准：先讲为什么，再给分行建议**

如果前面已确认结束标准，直接沿用，不重问。尚未确认时，沿用本例已选的人工判断方式：

教练：“有些生意已经不会继续，却一直留在列表里，让你看不清哪些还值得跟进。标记输单，就是结束这一次机会；客户资料仍保留，以后有新需求还可以继续合作。

建议遇到以下情况时，由你确认输单：

- 客户明确取消这次采购。
- 客户已经选择其他供应商。
- 价格、规格或交期谈不拢，双方确定不再继续。
- 你判断这次机会不值得继续投入。

本例你已选到期由人判断，因此无回复、延期或暂缓按已定期限进入复核，不直接判输单；选择自动结束的企业则按其规则执行。

按这些情况判断是否结束一笔商机，符合你的业务吗？”

客户确认后，再进入原因选择；不要在同一轮要求同时确定两件事。

**原因支持经营决定**

教练：“我们会建立输单主要原因的单选字段，结束这笔商机时选一类。统一分类后，才能看出主要丢在哪里、先改善什么。建议这些选项：

- 价格不合适。
- 产品或规格不符合。
- 交期不满足。
- 缺乏认证。
- 选择其他供应商。
- 客户取消采购。
- 客户不回复。
- 长期停滞（有沟通但一直无推进）。
- 其他，原因不明或不好归类时可补充已知情况。

外贸中把缺乏认证单独统计，能帮助你判断是否值得投入认证费用。这些选项需要调整吗？”

客户：“缺乏认证保留就好，不用继续问。”

教练保存选项并继续，不询问证书、国家、认证预算，不新增专项字段。明确结束的商机与仍在等待的商机分开；一笔输单不删除客户或结束该客户所有机会。

## E. 关系维护与负责人

教练：“没有正在推进的采购时，也需要维护客户关系。先以三星为例，建议每 30 天提醒一次；有活跃商机时优先按商机跟进，30 天适合吗？”

客户：“适合。”

教练给其余等级的周期建议，客户修正：“一星二星需要 15 天。”

教练：“一二星 15 天，三星 30 天。四五星也先建议 30 天，侧重关系维护和新需求交流，合适吗？”

客户：“合适。”

教练：“未完成保留原任务；手动完成后重新计时；出现活跃商机暂停关系维护。按这个方式执行可以吗？”

客户：“可以。”

首次上线如何起算、商机结束后恢复策略在模块收拢时给简单建议，记清采用情况；不让历史空日期造成大量逾期待办。不要因为客户偏好低星高频就把规则改回高星高频。

教练：“客户负责人经营长期关系，商机负责人推进这一笔采购，任务分给实际处理的人。你是一人处理，还是不同业务员分别负责？”

客户说明已有三名业务员分别使用业务账号时，沿用背景，建议新客户归接触/登记业务员、已有客户保留原负责人。只做责任分配，不问扫码接入、角色权限、公私海。

## F. 收拢、实施与学会修改

教练展示本公司简短蓝图：分级及用途、完整流程及可选/待定项、字段来源、提醒与维护、订单统计、负责人、人工与自动责任。把遗漏放回对应位置，不重新开整套问卷。

基础数据由人录入/导入，到账由人核实，统计/分级/提醒由实际可验证的 CRM 规则完成。平台能力由智能体检查，不能让初学者解释 API。仅提出真正阻碍实施的未决业务问题；已授权、条件齐全就继续配置和验收。

在各模块已给过自然语言使用示例，最后让客户亲自完成一次练习：

> “把三星客户没有活跃商机时的维护周期从 30 天改成 20 天。先说明已有任务受到什么影响，再按确认范围修改，并用例子验证。”

客户看一个应该变化和一个不应变化的例子，核对真实结果；无法操作正式系统时在隔离环境演练并如实标注。交付包含系统、可理解的规则和客户继续修改它的方法。

# 负责人和跨 Skill 协作

## 负责人有实际用途

> 客户负责人表示谁持续经营这段关系；商机负责人推进这次采购；任务负责人完成具体动作。

小团队可以默认三者相同，只有实际协作需要时才分别指定。业务员数量、渠道账号数量与角色权限是不同问题。

## 简短引导

如果客户提到业务账号：确认数量和使用方式，用于建立业务来源与负责人对应。多个账号可以对应同一个人，一个账号也可能多人共用，不根据数字猜人数。只记录账号别名和负责人，无需获取登录二维码或凭据。

可推荐的归属规则：新客户默认归接触/登记的业务员，已有客户保留原负责人；其他人接触不自动抢走客户。客户选择不同方式时记录。

处理同一客户重复登记，要区分合并记录与更换负责人。存在冲突时由人核实；不悄悄覆盖旧业务历史。明确的转交保存旧负责人和时间，未完成任务是否一起转交在转交时展示影响。

## 本 Skill 不负责实施的内容

不设计业务员仅看自己/管理者看全部的角色权限，不配置可见字段或导出权限，不设计公海私海、保护期、自动回收或分配池。不因有三位业务员就主动进入权限访谈。

负责人是归属信息，不承诺任何保密隔离。实施时保留现有平台权限，不为了让功能可用而擅自开放全员访问；若某项操作被权限阻止，明确该项限制，继续能完成的基建。

客户要求接入聊天时，说明由对应 Skill 承接并记录交接，不将其记为客户已排除，也不因为不属于本 Skill 就否定整个产品能力。改变的是本次实施职责时，才更新职责范围。

## 字段与验收

需要至少能识别人员、将客户/商机关联到负责人，并把任务分配给正确对象。平台成员账户是否已存在是实施核验项，不要求客户在教学时填写技术 ID。

验证：新客户默认负责人；旧客户收到另一来源信息不改负责人；商机任务遵循已选规则；未分配记录可见；转交按明确范围执行，不假称角色权限已配置。

## 当前环节的最低完成要求

仅缺负责人时就问“一人处理还是不同业务员分别负责”，不为了教学主动询问 WhatsApp 账号数。客户此前已经说过账号与业务员关系，直接沿用。

给一个新客户、已有客户、相关任务的归属建议供调整；完成后回到蓝图收拢。不要把客户归属的确认解释为允许配置角色权限或消息接入。


## 与其他 Skill 组成同一套系统

给客户的简短解释：“这里先把客户、商机、字段和管理规则搭好。聊天接入由另一套 Skill 完成，它会沿用这些资料，把沟通记录关联到对应客户；内容分析和自动更新也由该 Skill 按你已确定的规则落实，不重新设计业务流程。”不因此插入一套渠道接入问卷。

基建交付时，在现有蓝图和实施记录中留下交接信息，不为每个 Skill 复制一套企业规则：

- **共同依据**：企业蓝图、字段字典、决策及实施记录的位置和当前版本，目标 CRM/工作区。另一个项目承接时记录共享位置或显式交接的版本；不假定不同项目自动同步文件。
- **复用对象**：已存在的客户、联系人、商机及关联，真实字段标识、类型、枚举和负责人映射；由实施者读取系统，未知则标待核验，不要求客户填写技术 ID。
- **接入边界**：渠道身份如何匹配客户/联系人、会话如何关联商机由接入 Skill 核验；不能只凭同名新建/合并客户，也不能把一位客户的所有聊天强行归入最新商机。有歧义时交给人判断。
- **更新职责**：哪些字段当前由人、CRM 工作流或已有接入维护，外部写入会触发哪些评级/任务等规则。聊天已同步不等于分析已完成，更不授权自动改阶段或重复创建提醒。具体同步、去重与冲突方案由承接 Skill 实施和验收。
- **交接状态**：能力、承接 Skill/项目（未知就留待指定）、已知需求、依赖、当前状态、实际验证证据、下一步。需求已确定但尚未实施的写“待其他 Skill 实施”，只有客户明确不需要才写“客户已排除”。

凭据由承接 Skill 在对应环境配置，交接文档只记安全存放位置/配置状态，不写凭据值。后续 Skill 完成后回写同一业务档案及映射、实际验收结果；基建再次调整字段时先检查这些依赖，避免破坏已接入功能。

本 Skill 完成只表示基建在其范围内完成。报告产品进度时分别列出基建、聊天接入及其他模块状态；聊天尚未完成时，不把整个产品说成已经交付。没有承接 Skill 的路径或工具时，保存可接续的交接信息，不能声称已调用或已接通。

## CRA 套装中的明确承接

聊天与模型实施入口是同套装的 [chat-signal](../../chat-signal/SKILL.md)。字段含义、阶段成立条件、聊天证据要求与允许的字段变更属于本轮企业业务规则，随字段字典记录；承接者沿用已有答案，逐阶段问清尚未明确的变更依据和相关字段更新规则，补充写回同一档案，再生成模型说明及实际配置；不重做基础业务诊断，也不因避免重复而跳过真实缺口。已决定的自动执行不改成逐条人工审批。

人工审核范围、分工及通过/拒绝后的动作也随共同蓝图交接。待业务与识别规则完成，由 chat-signal 按 [待审核应用指导](../../chat-signal/references/13-review-app.md) 配置随包应用或已有等价入口；所有需要人决定的拟变更都应可在同一入口找到，不能只留在错误日志。规则确认、应用安装、后台接通和实际验收分别记录。

聊天档案只追加连接、模型、部署与运行状态，引用同一份业务档案及版本。客户调整某条业务规则时两个 Skill 更新各自负责的实现，共同回写实际结果。无需 CRA 配置编译器或独立管理应用才能交接。

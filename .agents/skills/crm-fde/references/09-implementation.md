# CRM 基建实施与验收

## 交付边界

这份手册指导智能体使用目标环境已有工具完成配置。它不附带通用 CRM 部署器，也不保证任何平台/套餐/版本都支持相同工作流。选用客户已有平台；Twenty 是可用目标之一，不强制迁移到它，不依赖作者原项目的凭据、对象 ID、服务或脚本。

先读取确认版蓝图、字段字典和实施记录。只有“建议”或演练中出现过的配置不能写到生产。已明确授权搭建的工作继续完成，不反复问可逆的小步骤；付费购买、对外消息等不能从“配置 CRM”推导授权。

## 1. 对齐可实施范围

蓝图达到本次实施就绪：

- 对象及关系已定，采用的流程节点和分支无关键歧义。
- 所有会执行的阶段/评级/统计规则有确定输入、来源和条件。
- 任务时区、起点、重复、完成和停止规则可解释。
- 每条规则有代表性正例和边界例。
- 未决项有影响范围；只冻结依赖它的配置。

展示简短可审阅摘要。确认与授权记录引用用户已有指令，不自行制造一个签字审批流程。

## 2. 盘点目标环境

优先用现有连接器、官方接口或 CLI 读取；可用时再用界面操作。明确目标实例、租户/工作区、版本、已有对象/字段/枚举、关联、工作流及实际可用能力。技术细节实施时检索对应版本的官方文档，不把教材或过时记忆当成接口契约。

对每一项能力记录为：已实测、仅文档支持、待核验、缺失。仅文档支持不能标为自动化已上线。

对 Twenty 或其他现成 CRM，优先核实：自定义字段与关联、金额和时区、原生任务、定时/事件工作流、条件分支、后台去重、订单汇总、字段编辑入口、导入/导出及恢复方式。无需客户理解内部 UUID，智能体负责按业务语义映射。

如果客户从零开始且需要安装 CRM：在独立的已授权环境核实官方安装方式、依赖、持久化、备份和升级路径，再实施。先给可检查的部署方案；不能拿作者本地开发环境的配置当可交付安装包。

采用 Twenty 时，继续读取 [Twenty 安装与配置经验](twenty/00-index.md)，其中包含项目提炼的部署、升级、密钥连续性、字段编码、跨实例映射、工作流激活、视图白屏和调度验收方法。按当前任务选择章节；不要一次加载全部资料，也不要执行原项目一次性脚本。

## 3. 映射而不是复制

先依据已确认蓝图完成 [确定性规则分析](twenty/05-workflows.md)：逐条覆盖客户关系阶段、商机阶段、等级和提醒，记录输入来源、触发、条件/计算、更新动作、唯一执行者及缺口。可确定计算的规则优先落实到 Twenty 工作流，混合规则拆开模型提取事实与工作流计算。crm-fde 负责这些工作流的实际配置、验证和启用，不把分析表作为完成结果交给 chat-signal。只冻结依赖未就绪的分支。

建立“业务字段 → 现有字段/新字段 → 关联/工作流 → 来源”表。比较含义，不只比较名称。保留稳定内部标识，显示名称可本地化。

- 重用等价字段和对象，不重复创建。
- 名称相同但含义不同先处理语义冲突。
- 前后枚举顺序、内部值、看板位置分别记录。
- 流程包含报价前后打样时，选平台真正支持的表示方式。
- 不把不可验证的时间或并发约束塞进说明文字后宣称已实现。

执行前导出或记录受影响配置，保存版本和恢复步骤。不要改动无关对象、现有访问控制或渠道服务。

## 4. 配置顺序

1. 建立/复用客户、联系人及必要人员关联。
2. 建商机及客户关系、采用的阶段/可选环节。
3. 建必要字段、输入类型与按阶段的检查条件；默认落实商机输单主要原因单选、企业选项及转输单时的原因校验，创建早期商机不强制填原因。
4. 建订单关联与统计，验证唯一关联和金额口径。
5. 配置客户分级，使用已验证的统计数据。
6. 配置商机任务、客户维护与去重；crm-fde对期限和数据已就绪的不回复/停滞规则，优先配置并验证Twenty工作流，按客户选择自动结束或人工确认。仅缺消息来源的规则记录依赖，不把全部期限规则推迟给chat-signal。
   同时逐条落实分析表中其他阶段、等级和提醒工作流；依赖顺序可以调整。阶段成立条件已由可靠字段证明时配置允许的自动推进，避免遗漏后只留下人工入口。
7. 调整列表/看板/详情，只显示日常有用的内容。
8. 用测试案例跑通完整路径，再按已有授权启用目标工作流。

依赖可调整，但不能让使用未完成统计的评级先批量覆盖真实客户。每一步记录实际改动和验证结果，失败时能够定位，而不是整套重复重建。

## 5. 本 Skill 独立实施时的数据入口

下列是尚无其他模块提供数据时的基建入口。若已有聊天或其他接入，先核验并保留实际来源和更新职责，不按本清单将它们改回手工；新增接入由其他 Skill 承接。

- 客户/联系人资料：人工录入、已授权导入。
- 采购需求、正式报价附件及发送时间等原始事实：无其他可靠来源时由人工录入。阶段按分析结果由已验证工作流推进或人工更新，不统一限定人工。
- 定金/尾款核实：人工查阅既有记录后确认，不连接财务系统。
- 跟进备注和任务完成：人工维护。
- 评级、统计、任务创建：平台具备且已测试的确定性工作流。

导入前做字段映射预览、重复记录检查和样本导入；不要把未知自动变成零，不凭文件列顺序匹配。原始数据保留，除非用户明确要求不需要某个持久文件。

## 6. 实际验收

使用 [验收模板](../assets/acceptance.md)。每项记录输入、预期、实测、结果证据和环境。至少覆盖：

- 同一客户两笔商机，状态/金额/任务互不混淆。
- 选定的完整流程，可选节点可跳过且不会丢掉已报价事实。
- 星级阈值边界、未知、取高与只升不降/纠错。
- 确定性规则的实际输入变化触发工作流并回读正确结果；综合等级不被多个执行者覆盖，计算链路无模型调用。混合规则缺事实时不猜值，已知事实入库后可完成下游计算。
- 赢单建单一次、重试不重复、金额修正和统计一致。
- 报价跟进、未完成不重复、第二次基于实际完成时间、上限与约定日期。
- 不回复/停滞仅复核或直接结束符合客户选择，使用正确起点和重置；原因与阶段同步保存。
- 输单原因的单选、其他兜底、条件必填及筛选汇总真实可用，重复执行不覆盖已有更具体的原因。
- 活跃商机抑制维护，维护完成和取消区别处理。
- 任务归属正确，未配置的访问权限不宣称通过。
- 人工按正常入口修改、相关视图及时显示、异常能定位。

只在范围需要时补更多测试，不为低影响文案变更跑全套。重复执行、并发创建等关乎重复订单和任务的问题有实际必要时必须核实，不能只看“运行成功”。

## 7. 失败与恢复

同一动作连续两次得到相同确定性错误时停止盲目重试，保存证据并重新检查能力、配置和权限。先完成不受阻的部分。没有权限时不更换身份绕过限制。

优先暂停受影响工作流或恢复对应配置版本。恢复配置不会自动撤销已发出的通知、已生成订单和已产生任务；逐项说明受影响记录和补偿动作。不要批量删除业务数据来“恢复”。文件删除也遵循一次一个明确路径、不删除目录的规则。

若不能完整实现：说明哪一条未通过、现有替代步骤、剩余工作。蓝图完成不等于系统已部署；演示数据通过不等于真实业务长期稳定。

## 8. 交付给客户与后续 Skill

交付完整业务蓝图、字段说明、工作流摘要、使用入口、例外处理和恢复方法、真实验收结果。记录哪些由人完成、哪些自动发生。同时按 [跨 Skill 协作](08-ownership.md) 保存对象字段映射、已有接入依赖与承接待办，明确基建完成不等于聊天模块完成。最后执行一次 [自主调整练习](10-adjustments.md)，让客户从使用者变成能提出并检查改变的人。

## 收拢时不要重新让客户设计一遍

在教学路线 C，主动生成本公司可读摘要：五星及用途、完整流程及可选/待定节点、主要字段与来源、提醒和维护、订单统计、负责人、人工/自动责任。来源是此前已确认记录，不再次要求客户填写空白模板。

未决内容分为：需客户决定的业务语义；可给简明建议集中确认的普通选择；智能体从目标系统查证的技术事实；本轮范围外的扩展。只有第一类关键缺口影响对应实施，不因未知 API 版本让客户重述业务。

条件齐全且已有授权就进入实际配置和验收；不要以“本 Skill 只是教材”为由停在蓝图。没有工具/连接时留下具体可继续的映射和缺口，如实说明未实施。

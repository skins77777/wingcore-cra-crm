# 业务蓝图与会话连续性

## 为什么必须有档案

长对话会遗忘或缩写上下文；企业规则不能只存在于聊天中。所有实施行为基于当前企业档案和实际系统状态。通用 Skill 可更新，企业已确认规则不能因此被重置。

使用六份相互引用的工作文件：蓝图、字段字典、决策记录、实施记录、验收记录、学习手册。客户已有类似体系时维护原文件。文件是工作记录，不是已自动生效的配置，也不替代实际系统核验。

## 状态使用两个维度

**业务决定**：参考建议 / 待确认 / 已确认 / 已排除 / 已被新版本替代。

**实施结果**：未实施 / 已配置待验证 / 已验证 / 受阻 / 已恢复。

不能用一个“完成”同时表示客户同意和系统可用。流程节点的“采用”与“进入条件”也可以分别标状态。

## 决策最少信息

稳定 ID、所属模块、具体规则、状态、来源（客户原话或资料引用）、日期/版本、依赖、实施影响。无需复制完整私密聊天，只保留必要的业务依据。

例：`G-AGG-01`，评级三指标取最高，已确认；`P-SAMPLE-01`，打样按客户要求启用，已确认；`P-SAMPLE-END-01`，打样完成条件，待确认。不要因为完成条件未确定，删除已确认的可选节点。

## 每轮更新方法

1. 找到当前主题和用户意图：客户业务答复，还是作者在修改技能。
2. 只修改涉及条目，保留无关确认与待定。
3. 新建议标为建议；客户清晰同意后改为已确认，保存其所指内容。
4. “可以”仅对应最近一个明确建议；如果一轮混合多个冲突问题，先收敛，不视作无限确认。
5. 用户纠正旧内容时，将旧规则标为已替代，保留变更原因，检查依赖。
6. 记录当前进度、上次待答问题和下一步，让恢复会话不重启访谈。

## 进入下一个模块的检查点

- 分级完成：三个指标及采用范围、阈值、取高/其他合并、升降、未知策略。
- 流程完成：整张图、赢单/输单、可选节点、顺序、哪些仍待细化。
- 提醒完成：覆盖表逐项对应完整已采用流程（含可选节点），每项明确需要/不需要/待定；需要提醒项的触发、动作、负责人、时间、完成/轮次、去重与停止规则明确且无冲突。待定或细节未决可以继续其他模块，但不能把提醒设计标为全部完成；流程变更仅复查受影响行。
- 订单完成：建单和统计时点一致，负责人/客户关联不会丢失。
- 实施前：输出完整蓝图，只提剩余真正影响执行的缺口，不要求从头重答。

客户想跳过某个未决问题，可以先做其他模块。字段、规则、部署能力的未知都需要明确留下，不能用推荐值假装已经选定。

## 职责范围与产品能力分开记录

本 Skill 不负责实施角色权限、公私海、聊天接入/分析/AI 改字段、财务系统联动。聊天接入由其他 Skill 承接，是完整产品的一部分。分别记录“本 Skill 负责”“其他 Skill 承接”“客户明确不需要”；不能将本 Skill 未实施推断成客户已排除。已有接入状态必须沿用。交接内容见 [跨 Skill 协作](08-ownership.md)。

“北京时间凌晨 2 点汇总新增对话”属于其他 Skill 承接的分析任务；它不自动成为原生维护任务的调度规则。负责人关联属于基建；三账号不等于已经建立三套权限或接入链。

## 防止两种混淆

- **模板与实例**：本技能的演练案例独立标为案例，不作为初次打开就应用的配置。
- **作者与客户**：用户审稿时发现遗漏，要修订教材路由和检查点；不要追问作者“你的客户到底怎样验收”，除非他明确切回企业实施。

## 恢复会话示例

合适：“已确认打样按需启用、可在报价前后，报价提醒两次，输单仅人工判断。当前在整理任务字段，继续补齐时间口径。”

不合适：“你是否需要打样？”或只展示“询盘—报价—成交”并忽略已选节点。

## 定稿与变更

用语义版本或明确日期修订号，记录关键变更。客户主动要求变化时更新业务记录，再核对真实系统；已部署但蓝图未更新属于需修正的不一致，不以文档版本覆盖现实。

不存密码、token、私人联系人数据或整段聊天到通用 Skill。客户档案与分发包分开，评估使用合成数据。

## 首次建档和每轮落盘

正式教学已有可写客户项目时，在第一次有效业务答复后建立或复用 `crm-foundation`。公司名未知可用明确的暂称“企业名称待补”初始化，记录它不是客户提供的真实名称，日后原位更新。不要为了调用初始化脚本先插入公司名称调查；不要重复运行脚本覆盖已有档案。

每轮完成三项更新：

1. 业务蓝图：本次确认/修改的参数、当前步骤、上次问题、下一步及必要返回点。
2. 决策记录：改变了什么、客户依据、建议/确认/跳过状态；同一选择不重复生成相互矛盾的记录。
3. 字段字典与学习手册：本轮新增字段的含义/用途/来源，以及已介绍的自然语言用法；无变化时无需重复写。

单纯回复“已记录”不能代替文件更新。没有可写项目、纯作者评审或客户要求只聊天时，不擅建企业档案；给出简短可接续状态并说明未持久保存。文件写入失败不能当作成功，先保留待保存摘要。

新会话先读业务蓝图的当前步骤和决策，再读当前模块教材，不仅加载主 Skill。暂停或跳过保留当前位置，补回遗漏只修改对应节点后返回原主题。

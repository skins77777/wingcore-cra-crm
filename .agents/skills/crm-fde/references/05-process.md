# 商机流程：先全貌、后细节

## 1. 首先解释商机

> 一条商机管理一次独立采购。同一客户可以同时有旧货在运输、新需求在询价。分开记录，数量、报价和跟进就不会混在一起。

新独立需求新建商机；同笔采购改量、改规格、改报价留在原商机。售后问题不默认新建销售机会。只有确有必要才深入复杂拆单/合单规则。

## 2. 先听业务，再交付完整流程参考

进入本模块后，背景不足时的问题：

> 请拿一笔典型业务来说，从客户第一次咨询，到你认为这笔业务完全结束，中间通常经过哪些步骤？我来整理成流程。

客户只说“咨询、报价、成交”已经足以先给参考，不要求其再凭空补齐。根据背景用下表整理一份完整参考，放在交给客户的同一份答复中。若此前已提供足够步骤，省略重新访谈直接整理。

| 参考环节 | 为什么值得关注 |
|---|---|
| 咨询／询盘 | 有采购意向，但资料可能不齐 |
| 需求确认 | 报价所需信息是否明确 |
| 打样／试用（可选） | 是否需要先验证，位置可在报价前后 |
| 报价 | 本次采购的正式方案是否已发出 |
| 签约／确认订单／付款 | 合作成立的依据与约定款项是否满足 |
| 生产／备货 | 履约准备进展 |
| 发货／配送／交付 | 是否交出货物或成果 |
| 签收／验收 | 客户是否收到并按约定接受 |
| 赢单（结果节点） | 哪个事实表示本次销售成功，用于成功率和合作贡献统计 |
| 输单（结果分支） | 中途明确不再推进，记录原因用于经营改进 |

表格不强制线性先后或每项都独立建阶段。根据行业替换或合并履约项，例如服务业务可用方案确认、服务执行、成果验收；未确认的不当成已选。赢单位置按客户定义，不天然排在验收后；输单是一条结果分支，不是赢单之后的下一步。可选打样不得因为简短而消失。

简短说明：“这些是供你删改的参考。输单只结束这次机会，不等于放弃客户。哪些环节需要增加、删除、合并或调整位置？”

这轮的交付是完整参考加一个调整问题，**不是**几个提示词加“请自己列出所有步骤”，也不是立刻追问定金比例。客户审阅后再进入细化。若只确认了部分，保存全部采用状态，针对剩余部分给具体合并建议收拢；不重问已经回答的步骤。

## 3. 完整流程表

每个节点记录：稳定标识、显示名、用途、采用状态、必经/可选、前后关系或分支、条件是否已定、关联任务。采用状态与细节状态分开：已决定保留打样，但完成条件可以待明确。

本地蓝图要保留暂未采用的参考节点及排除理由。未选节点不能自动创建到 CRM；排除节点也不能在下一轮被偷偷加回。完整流程审阅后才进入以下阶段细化。

## 4. 可选与不固定顺序的环节

打样是典型：先问是否每笔都需要，还是客户要求时才需要；再确认在报价前、后或两种都有。按答案建模，不将“可选”误当成“删除”。

如果两种都有，保留销售进度和报价版本。可采用独立打样状态、关联任务/子流程，或平台支持的条件分支；具体实现由现状核验决定。不要强迫所有机会在单一线性看板上来回跳，导致旧报价和阶段计时失真。

完成标准另行定义，如样品寄出、客户收样、确认通过等。不能因为教材以确认通过举例，就自动写成客户已确认规则。

## 5. 每个阶段的逐步提问

采用节点按下表给具体建议后再问，不把这一表原样作为整套问卷发送。客户已有答案直接收拢。

| 节点 | 可采用的简短讲法与下一问 | 回答后形成什么 |
|---|---|---|
| 需求确认 | “产品、规格、数量、地点和期望交期齐了就能报价吗？” | 该阶段的最少业务资料及用途；本次数量与月采购潜力分开 |
| 报价 | “正式报价已发送才算，通常用 PDF、图片还是明确的聊天报价？” | 报价载体、版本和发送事实；发送时间用于提醒，不将上传当发送 |
| 成交 | “确认采购就算，还是至少收到款？”；若定金，再问“固定比例还是每单约定？” | 接受订单/款项条件、约定门槛及人工到账核实，不直接问财务软件版本 |
| 打样 | “每笔都要还是按需？”再问“报价前、后或两种？” | 采用条件与位置；完成依据另给建议，不擅自确认样品通过 |
| 签约/备货/配送/验收 | 给该节点可观察的起步定义，如正式发货或客户确认接受，再问是否合适 | 一个明确进入/完成依据及必要记录；只处理客户选择保留的节点 |
| 赢单 | “哪个节点表示这次机会成功，例如定金到账、交付完成或尾款收齐？” | 客户的成功口径；只收尾款的回答不附加验收条件；随即衔接订单统计 |
| 输单 | 主动建议处理明确失败及长期不回复/无推进，按采购周期给结束规则供调整 | 适用阶段、时间与动作；必建原因单选选项，复核选择不擅自变为自动结束 |

每次新采用关键字段，在当轮或紧接的规则摘要中解释含义、用途、来源/更新者。无需讲 API 类型；读 [字段字典](03-fields.md) 补足定义。完整连续讲法见 [示范 B–D](14-dialogue-walkthrough.md)。



一次只处理一个决定：

1. 这个阶段让你看见什么进展？
2. 什么明确事实足以进入？给一个推荐起步定义。
3. 到这里必须有哪些信息？按阶段要求，不让所有字段在创建时必填。
4. 通常下一步做什么？需要提醒时转任务模块。
5. 结束/跳转的条件是什么？关键异常放本节点，不在后续模块重开整个流程。

示例：客户已选择“成交”节点 → “确认采购就算成交，还是要收到款？” → “至少定金” → “固定比例还是每单约定？” → “每单约定” → 汇总为“客户确认下单、约定定金已核实到账”。接着记录字段依赖和人工来源，不在本版追问金蝶产品。

以下是概念参考，只有客户采用后才进入实施：

| 节点 | 可用起步定义 | 需要防止的混淆 |
|---|---|---|
| 询盘 | 有采购意向，信息尚不足以正式报价 | 普通问候不自动成为新采购 |
| 需求确认 | 已拿到准备报价所需信息 | 开始聊需求不等于需求已明确 |
| 报价 | 针对该采购的正式报价已发送 | 价目表、内部草稿、上传文件不等于已发正式报价 |
| 签约 | 合同达到约定确认状态 | 草稿与双方接受版本不同 |
| 成交 | 公司认可的合作成立条件已满足 | 不一律等于全款到账 |
| 生产/备货 | 已进入实际准备 | 排期或客户意向不等于已开始 |
| 配送 | 公司定义的发货/运输节点 | 不能默认包括备货，除非客户选择合并 |
| 验收 | 按约定完成接收和质量确认 | 签收不一定等于验收通过 |
| 赢单 | 公司定义的一次销售成功 | 可以在交付前，不强制所有企业等收货/货损/全款 |
| 输单 | 明确失败，或达到企业约定的不回复/停滞结束条件 | 不能忽略长期不回复，也不能未定期限就凭一次沉默判失败 |

若采用“需求确认”，通常介绍产品、规格、数量、交货地点、期望交期，并问足以报价否。服务行业按成果范围、人数、工期等改写，不套用实物货物字段。

## 6. 赢单与订单要同时衔接

确认赢单标准时，同时记录它如何影响订单和客户统计。如果选择赢单才建单，来源商机必须唯一映射，重复保存不能重复统计。若企业在签约就建单，则另设计入成交统计的时间/条件。详见 [订单与统计](07-orders.md)。

到账依据在本版采用人工核实确认。可以记录“未来财务系统来源”，不能因知道产品名就承诺自动联动。赢单后退款、撤销或更正不能不加区分地变成普通输单。

## 7. 输单规则与原因

输单既包括明确放弃，也应覆盖长期不回复或长期无推进的机会。主动解释：“一直挂着的商机会让你高估可成交机会，也占用跟进精力。建议给长期不回复、没有实际进展的机会设结束规则，转为输单并记录原因；结束的是这次机会，客户资料和历史仍保留。”不能等客户自己想到这项管理需要。

分轮讨论明确结束、停滞处理及期限、原因选项，不一次发整套问卷。主动给出结合企业采购周期的建议，请客户调整；不要把“没回复绝不能输单”或“到期一律只提醒”当通用规则。客户选择到期自动输单则记录执行条件，选择人工确认则进入现有复核/待审核入口，不能擅自改变选择。

停滞规则至少明确：适用阶段、起算事件、多久、什么算有效回复或实质推进、是否重置、约定延期怎样处理、到期自动结束还是人工确认。客户已选阶段停留时不改成最后聊天；按客户回复起算时，销售反复发送消息不能自动替客户重置计时。不要将售前规则直接套到已收款、履约或争议处理；终态不再参加普通停滞检查。没有企业确认的期限与范围，不默认采用教材或别家企业的天数。

### crm-fde配置期限工作流，chat-signal再复核

上述结束规则在crm-fde阶段就主动提出并与客户确认，不仅建设原因字段。期限、适用阶段及计时字段明确后，在目标Twenty具备所需能力时由crm-fde配置并验证工作流，按规则转输单及保存原因，或创建人工确认事项；实施见 [确定性期限工作流](twenty/05-workflows.md)。

阶段进入时间等CRM已有数据足够的规则不依赖大模型即可实施。若采用“最后客户有效回复”等消息依据，必须核实时间字段已由可靠来源维护；尚未接入时记录该规则的数据依赖，不将空值当长期未回复，也不偷偷改成阶段停留规则。chat-signal后续负责接入/识别，并像其他步骤一样带客户重新考虑原规则。规则未变则沿用已验证的工作流，有变化同步调整原实现，保持一个期限执行者。

### 输单原因是标准基建

采用商机管理时，**默认必须创建或复用“输单主要原因”单选字段及固定选项**，不等客户主动要求，也不能仅留自由文本或备注。讲清用途：统一分类才能按原因、阶段和时间汇总，判断优先改善价格、产品、交期还是跟进方式。客户确认行业选项；若客户明确拒绝该基建，记录其决定及失去的分析能力，不默默省略。

至少提供“客户不回复”和“其他”两类，并建议以下原因供客户调整，给客户时分行展示：

- 客户不回复：满足该企业已确认的无回复结束规则。
- 价格不合适。
- 产品或规格不符合。
- 交期不满足。
- 选择其他供应商。
- 客户取消采购。
- 长期停滞：企业采用停滞结束策略时可选；有回复但长期无推进不能冒充不回复。
- 其他：无法可靠归入上述类别，含未说明具体商业原因；可补充简短说明，不强编原因。

外贸可增加“缺乏认证”，保留独立统计价值，不自动展开认证专项访谈。已有“客户未说明”等历史选项可保留，核对含义及统计映射后再调整，不能直接删除或无依据重写历史。

每笔输单记录一个主要原因，可配补充说明及消息/计时依据；多种因素时按已确认优先级选择主要原因，不能随意选一个。明确报价太贵而取消可记价格，不因后来沉默就覆盖为不回复；只有计时结束依据时，不推测价格或竞争对手，按实际触发记录不回复、长期停滞或其他。

字段在标记输单时必须有合法选项，创建早期商机时不要求填。手工操作、确定性工作流和chat-signal自动更新都使用同一组选项；平台不支持条件必填时，在实际可用的阶段变更入口或写入流程校验阶段与原因一同保存，不把文字要求当作已实现。固定选项的稳定标识、来源和维护职责写进字段字典。

输单后同需求重启采用重开还是新机会，需要一个明确规则；保留原输单原因和时间历史，不能一次重开就抹掉后续分析依据。一笔输单不删除客户、不结束其他商机；赢单后退款按订单修正规则处理。

## 8. 流程验收

用一笔典型赢单、一笔输单、一笔多次报价、一个可选环节测试。分别检查：是否丢节点、是否能跳过可选环节、报价版本是否保留、时间是否重置正确、统计是否只发生一次。

若只想检查当前阶段自动化，不重新访谈此前已定的销售流程。发现遗漏时修正该节点并回到原主题。

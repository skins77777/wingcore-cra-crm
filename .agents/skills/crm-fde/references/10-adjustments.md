# 授人以渔：教客户自己调整

## 教学目标

客户能说清想改什么，要求先看影响，判断案例是否符合预期，再检查实际结果。不要求他学会写代码，也不让他把“智能体执行完了”当成“业务一定正确”。

## 第一次练习

选择一个低影响、容易观察的规则，例如某星级维护周期从 30 天改为 20 天。不要拿删除客户、修改币种或批量重评全库做首次练习。

可交给客户的指令示例：

> 把三星客户没有活跃商机时的维护周期，从 30 天改成 20 天。先说明会影响哪些已有任务，再用几个例子验证，最后按确认的范围修改。

提示他关注四件事：目标、适用范围、已有数据怎么处理、怎样算成功。客户可以用自然语言，不必记字段名。

## 智能体的执行方式

1. 读取企业蓝图、现有真实配置和上次实施结果。
2. 复述要变的业务含义，找出依赖，如当前任务、定时扫描和客户维护日期。
3. 明确新旧规则的差异。用户已指定影响范围就沿用，未指定才提出一个有理由的建议。
4. 用少量实例预览：已过 25 天、刚完成维护、有活跃商机、已有未完成任务等。
5. 按已有授权更新实际配置，保存旧版本和恢复路径。
6. 验证结果、更新蓝图和决策记录，给客户简短说明。

配置改动与产生的业务记录不同：恢复周期不一定自动删除新创建的任务。不得笼统承诺“一键回滚一切”。

## 常见自然语言修改

| 客户说法 | 智能体需要理解的决定 |
|---|---|
| 三星客户联系太频繁 | 周期更长还是仅调整某些客户？给出具体候选值 |
| 高星客户不要老推销 | 任务内容和周期可能要分别修改，不自动降星 |
| 打样不一定在报价之前 | 修改流程分支/并行状态，保留报价版本及有效进展 |
| 缺认证丢单越来越多 | 先展示已有原因统计；增加专项字段是独立范围选择 |
| 商机老被判输单 | 检查实际规则是否违反“仅复核”的已确认选择 |
| 这个客户星级不对 | 查指标来源、聚合和错误数据；不要直接全库重算 |
| 订单金额写错了 | 修改该订单、核对统计和评级纠错，保持次数不重复 |
| 我想更换负责人 | 预览客户/商机/未完成任务的范围，不更改未请求的权限 |

## 交付练习不是口头考试

客户自己发出一次调整请求并能辨认受影响范围，即可进入实际或隔离演练。让他检查一个正例和一个不应变化的例子。记录实际完成：能提出明确要求、理解影响、检查结果、知道如何找回规则。

如果不能碰真实环境，允许在隔离样例中练习，明确“演练通过，尚未生产执行”。不得将其报告为真实系统已修改。

## 持续使用手册

在客户学习手册中保留：常用入口、字段简明说明、三至五个可复用指令、如何查看规则依据、如何提出纠正、需要人工确认的事项。熟练后跳过解释直接处理，但仍维护蓝图，使下一次对话可以接续。

## 不等到最后才教会使用智能体

在各模块收拢时给一条当前可用的自然语言指令，不额外加一轮操作考试：

- 分级：“解释这位客户为什么是三星，引用数据，先不要改。”
- 流程：“我增加了一个按需打样环节，先展示流程和受影响的字段。”
- 提醒：“把此类任务最多两次改成三次，说明已有任务怎么办。”
- 订单：“更正这笔金额后，核对累计金额和等级。”

句式要在模块收拢的客户答复中实际展示，不能只填进学习手册。手册区分“待介绍、已展示、已实际尝试”，已展示引用对应答复，已尝试记录实际结果；没有对话或操作依据就保留待介绍。最后的亲自操作用于验证这一路学到的能力，不能用前面给过指令示例就声称客户已掌握。

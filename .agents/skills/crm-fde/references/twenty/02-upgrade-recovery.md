# 升级、密钥、备份与恢复

适用：接管旧实例、更换镜像、云端配置导入前的恢复准备。证据：原项目 `v2.22.0` 定制镜像原地升级至 `v2.40.0`，保留已有 PostgreSQL 16 和数据卷。

## 备份必须覆盖哪些内容

| 材料 | 本项目做法 | 为什么需要 |
|---|---|---|
| 业务与配置数据库 | `pg_dump` custom format | 包含业务数据、对象、字段、视图、工作流等 |
| PostgreSQL 全局对象 | 单独导出角色/全局对象 | 单库备份不自动覆盖所有角色依赖 |
| 本地附件 | 归档文件存储卷 | 数据库里的附件记录不包含文件本身 |
| 部署配置与密钥 | Compose、环境配置，敏感文件权限 0600 | 还原地址、挂载、加密能力；不得放入 Skill 包 |
| 旧定制运行环境 | 旧镜像导出、Dockerfile、补丁 | 官方镜像可能没有定制筛选器等能力 |
| 备份索引 | 时间、版本、大小、校验和、存储位置 | 判断恢复的是哪次状态以及文件是否完整 |

备份的一致性要按当前写入量设计：必要时短暂停写、记录截点，让数据库与附件能对应。日志中只输出路径和校验结果，不输出密钥。敏感备份与可分发配置经验分开保存。

本项目把数据库备份恢复到隔离 PostgreSQL 16 后，核对了工作区、对象、字段和工作流数量。这个结果证明当时数据库备份可读；不等于所有附件、密钥、旧镜像的完整灾难恢复都已演练。新客户应补充附件打开、登录、关键密文读取和代表性记录关系验证。

## 不改丢已有数据卷

升级前读取实际 Compose 项目名、卷名与服务挂载，而不只查看 YAML 中的短名称。Compose 项目名改变可能创建一套新卷：此时看到空系统，应先排查是否连接了新卷，不能立即导入或重建原数据。

本项目沿用了 `twenty-local` 与历史三个命名卷。不要执行带删卷选项的停栈操作，也不删除旧卷来解决迁移错误。备份验证使用隔离目标，不能恢复到仍在服务客户的数据库上。

## 密钥连续性：先判断旧环境

| 旧环境情况 | 第一次升级启动的处理 |
|---|---|
| 旧库已使用独立 `ENCRYPTION_KEY` | 保留该密钥，按对应版本升级规则处理 |
| 旧库未设置独立加密密钥，实际用旧 `APP_SECRET` 加密 | 本项目将同一个旧值作为首次升级的 `ENCRYPTION_KEY`，并保留旧 `APP_SECRET` |
| 多份环境配置矛盾、实际加密来源不清 | 暂停密钥变更，读取部署历史和验证现用密钥；不能猜一个新值 |
| 全新空实例 | 按当前版本新装要求生成独立随机密钥，无需继承作者值 |

升级与密钥轮换分开实施。历史 access/login/refresh secret 在这次升级中先保留，登录/API/加密值验收后才评估处理；这不是要求新装永远配置所有旧变量。

当前官方升级文档说明静态加密可能使用 `ENCRYPTION_KEY` 或旧 `APP_SECRET` 回退，并提供升级状态入口；具体跨版本路径及数据库要求应按待升级版本核实。[官方升级文档](https://docs.twenty.com/developers/self-host/capabilities/upgrade-guide)

## 执行顺序与停止条件

1. 记录旧版本、定制功能、磁盘和数据库状态，明确本轮升级范围；保留原配置。
2. 完成备份并在隔离目标验证恢复，记录未覆盖的恢复项。
3. 核对 server/worker 目标镜像一致、卷不变、密钥连续，按目标版本确认数据库兼容性。
4. 在已授权维护窗口启动升级，观察实例和各工作区迁移。不要同时改公司字段、清工作流、换存储和轮换密钥。
5. 检查目标版本支持的升级状态命令；当前官方提供 `yarn command:prod upgrade:status`，应在确认的 server 容器内执行。不要把容器健康状态替代迁移状态。
6. 迁移错误反复出现在同一步时保留日志和版本，不无限重启、不跳过数据库迁移去强行进入页面。
7. 登录、API、关键字段/关系、附件、工作流及页面验收后，再执行业务配置迁移。

本项目按风险节点另做了工作流导入前、旧流程替换前、视图修复前、字段对齐前快照。可复用的是“每次重要变更能回到明确基线”，不是机械要求每改一个标签都全库备份。

## 恢复决策

- 单项标签或草稿错误：恢复对应配置，避免全库回滚。
- 工作流产生了额外订单/任务：先停受影响流程，清点具体记录；配置回滚不会撤销业务副作用。
- 数据库迁移后不能简单换回旧镜像：旧程序可能不认识新结构。恢复应使用匹配的数据库、文件、密钥、配置和镜像组合。
- 存在升级后新业务：先保存增量并明确如何重放/补偿，不能直接把客户恢复到过去而丢掉新增业务。
- 原项目逐个处理旧工作流、孤立筛选器属于当时的定点修复，不是通用清理步骤。不得借升级批量删除客户数据、文件或目录。

交付时记录实际恢复测试范围、耗时、结果、备份位置和负责人。未经演练不要填写“已具备完整一键回滚”。

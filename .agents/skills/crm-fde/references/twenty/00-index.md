# Twenty 安装与配置经验手册

这份手册把原自动化 CRM 项目中的部署、升级、迁移和排错经验提炼为可复用方法。它随 `crm-fde` 独立分发，不需要原项目的账号、源码、数据库或脚本。原始来源仅用于追溯。

## 何时读取

客户选用 Twenty，正在安装、配置、升级、迁移或排错时，先读本页，再按当前问题读取下表。业务诊断仍按主 Skill 推进；不要把运维细节一次讲给初学者。

| 当前任务 | 按需读取 | 关键产物 |
|---|---|---|
| 新装、接管环境或配置公网入口 | [01 安装与环境](01-installation.md) | VPS/本地位置、版本、公网方案、内部地址、持久化与运行责任 |
| 旧实例升级、备份恢复 | [02 升级与恢复](02-upgrade-recovery.md) | 可恢复备份、密钥连续性、升级状态 |
| 云端/本地配置迁移 | [03 元数据与映射](03-metadata-migration.md) | 语义差异、ID 映射、最小变更计划 |

| 从蓝图识别阶段/等级/提醒的确定性规则，或统计、赢单建单、流程干扰 | [05 工作流](05-workflows.md) | 自动化分析、配置、依赖、激活、真实触发验证 |

## 证据与版本

- **项目已验证**：指原项目记录了实际执行及结果，主要基线为 2026-09-20 的自托管 Twenty `v2.40.0`。本手册整理时没有重新运行真实系统验收。
- **代码依据**：在源代码中找到实现，不能据此声称所有分支、并发或其他版本已经实测。
- **官方依据**：2026-09-20 查阅的官方在线文档。它会变化；实施前按目标版本再次核实。
- **实施建议／待验证**：从经验提炼的方法或客户目标环境尚未验证的能力。必须写入当前验收记录，不伪装成平台保证。

项目历史经历过早期本地探针、云端使用、本地旧定制版 `v2.22.0` 升至 `v2.40.0`、迁入云端业务配置。各时期的结论不能混用：早期 `v2.9.0` 探针不是后续版本能力的替代证据；旧文档“本地冻结”也不代表迁移后的状态。

## 实施时保持的约束

1. 先确认客户的目标实例、工作区与业务蓝图，再操作。源、目标、测试三者分别记录。
2. 迁移配置不等于迁移客户资料，也不等于覆盖整个工作区。明确迁移哪一类资源。
3. 按内部名和业务意义建立映射，保留目标实例身份；不复制作者的 UUID、凭据、公司阈值、汇率或端口作为强制默认。
4. 官方 API、UI、CLI 是优先入口；原项目的内部数据库补丁和自制认证令牌不进入客户通用安装流程。
5. API 成功后回读，后台正常后打开真实页面，工作流激活后检查真实事件。三者各自提供不同证据。
6. 保留可选打样、赢单、输单及客户已确认流程。本手册中的历史七阶段只解释编码，不能替换客户设计。
7. 聊天接入、AI 自动改字段、财务联动、业务角色权限和公私海不由本 Skill 实施；聊天由其他 Skill 承接，复用基建。扩展附录可为承接模块提供经验，不代表已经启用这些功能。

基础实施完成的标准：客户能从正常入口录入并处理业务，字段与规则可解释，范围内自动化有实测证据，客户完成一次低影响调整。容器启动、字段创建或文档完成都只是其中一步。

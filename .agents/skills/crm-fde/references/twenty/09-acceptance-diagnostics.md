# 验收、故障定位与客户交付

适用：安装或配置收尾、接续前一个智能体的工作、排查“看起来都对但没有生效”。记录在客户档案，不把历史结果当当前环境的勾选项。

## 五层证据

| 层 | 要验证的内容 | 足够有用的证据 |
|---|---|---|
| 运行环境 | 版本、卷、服务、迁移、worker | 目标身份、状态摘要、迁移结果 |
| 配置契约 | 字段、枚举、关系、视图、工作流 | 配置回读与蓝图/映射对照 |
| 业务行为 | 代表性业务能按规则执行 | 测试输入、前后记录、run/任务结果 |
| 用户界面 | 正常登录、导航、录入、显示 | 使用正常入口的操作结果或脱敏截图 |
| 维护能力 | 备份恢复、排错、客户自行调整 | 恢复演练范围、客户实际修改记录 |

每条结果注明：环境、版本、时间、执行方式（真实/模拟/只读）、预期、实测、证据位置、通过/失败/待验证/不适用。不要只留下“全部正常”。

## 按范围选取验收用例

基础安装：

- 登录后能进入目标工作区，server 与 worker 版本一致，数据库迁移无失败。
- 测试记录和附件在服务重启后仍能读取；备份至少完成一次隔离数据库恢复核对。
- API 和 UI 指向同一目标，正常浏览器会话没有初始化白屏。

字段与流程：

- 一客户两商机、两联系人，关系和字段不串用；样例金额包含小数及币种。
- 星级阈值边界、未知值、多指标取高，符合客户已确认规则。
- 完整流程包含客户选定的可选打样、赢单、输单；“缺乏认证”只是可选输单原因，不强制所有客户使用。
- 看板位置、枚举标签与内部值一致，列表与详情均能维护关键字段。
- 已有公司关联的联系人不被内置流程改绑；若自动创建公司在范围内，另验无关联成功路径。

范围内自动化：

- 赢单建单、事件重放、金额修正、统计回冲及并发约束，按 [工作流矩阵](05-workflows.md) 验证。
- 提醒起点、约定日期、完成后下一次、未完成去重、次数上限、停止条件和负责人。
- 使用客户时区，区分手工触发与真实定时触发。没等到真实窗口就如实记待验证。
- 一次失败恢复之后，业务记录、订单/任务数量和运行日志相互对应。

扩展 App/外部服务只在已启用时验：页面→服务端函数→外部服务→回读、成员身份、未授权访问、离线恢复、幂等与冲突。未启用的扩展标为不适用，不为了完成表格顺便安装。

## 故障诊断表

| 现象 | 优先区分 | 下一步 |
|---|---|---|
| 启动后像空系统 | 连错实例、项目名/卷变了、工作区变了 | 只读核对 context、挂载与身份；不重建数据 |
| 升级后加密值不可用 | 密钥不连续、配置未传入、版本路径不匹配 | 对比受保护的配置来源及升级日志，不输出密钥 |
| 页面白屏但 health 正常 | 不支持的旧视图/筛选器、前端初始化错误 | 导出受影响元数据、检查浏览器错误，读 [视图手册](06-views-troubleshooting.md) |
| 工作流 ACTIVE 但不执行 | 激活版本、事件注册、条件、worker | 检查真实 run 和触发前后记录 |
| 条件修改后仍是旧行为 | 改了草稿、另一个旧流程仍在运行 | 对照激活版本与所有同字段写入流程 |
| 公司/订单变多 | 内置自动建公司、重复触发、并发查空 | 先暂停出问题入口，定位具体 run 和业务键 |
| 金额差几个数量级 | 元/分/micros、币种错位 | 回读原始复合值，不凭页面数字再次覆盖 |
| 提醒时间差一天 | UTC 日期、客户时区、日期字段误转换 | 按客户业务日重算并检查实际执行器 |
| HTTP 200 但没变化 | GraphQL errors、接口忽略、改错实例 | 看 body、回读身份/字段、查错误码 |
| 容器里连不上 localhost | 调用者网络空间、内部服务名 | 验证同网络可达地址，别先暴露公网 |
| 唯一约束修复报已存在 | 元数据表现与实际索引不一致 | 核实实际约束，避免重复创建 |

同一动作重复出现相同确定性错误后，停止盲重试并重新诊断。网络短时异常可按已验证的有界重试策略处理；冲突、权限、schema 错误不能按网络错误无限重发。

## 历史验收的有效边界

原迁移记录提供了：数据库恢复成功、迁移成功、业务元数据与工作流映射、独立浏览器看板通过、关联保护、受控本地写入和离线恢复。其测试计数是当时仓库版本的结果，本手册整理没有重跑原业务系统。

尚不能由这些记录推出：任意客户全新安装可一键完成、所有版本兼容、原生统计无并发竞争、Twenty App Cron 已自动执行、生产容量达标、全链路灾难恢复通过、所有真实成员 UI 权限验证完成。

## 给客户的交付表达

先说已经能做什么，再列影响使用的待验证项。例如：

> 客户、商机、订单和星级规则已配置，并用两笔样例业务跑通。提醒的手动测试已通过，真实定时执行还未到验收窗口，当前不能算自动提醒已验收。你可以先按学习手册修改一条测试任务，我们一起确认结果。

实际交付清单：入口与承载方式、客户可读字段说明、完整流程图/表、人工与自动责任、备份位置与恢复范围、失败时找什么证据、未决事项、一次客户自主修改练习。技术实现细节保存在实施记录，客户日常界面以业务语言呈现。

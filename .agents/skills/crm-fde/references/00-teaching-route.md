# 教学执行路线：传递已经打磨过的经验

本 Skill 是一套教学与实施方法。不要仅把各章节当知识库，然后自行设计访谈。以下路线适用于从零开始的客户；已有选择、明确跳转、现有 CRM 和作者评审优先，跳过已有答案而不重置规则。

## 固定什么，允许调整什么

固定：主动解释价值、给具体建议、量化、客户调整、记录决定、验证理解，以及商机先全貌后细节。保留已确认选择，不靠重新提问恢复记忆。

可调整：行业用语、单位和周期、建议阈值、采用哪些业务节点、每轮表达长度。采用教材中的提问结构与参考模板；不可因为“因人而异”就省掉建议，让客户从零设计 CRM。例子里的数字不自动变成客户配置。

五星和下表模块是教学参考。客户采用其他分级、已经有成熟规则或明确不需要某模块时，沿用其选择并调整或跳过对应步骤；完成条件只检查实际采用的能力，不能为了走完路线恢复已排除项。

## 从零开始的路线与完成条件

| 步骤 | 智能体这一步必须做什么 | 怎样结束并进入下一步 |
|---|---|---|
| B0 最少背景 | 未知时只问产品/服务与客户类型；已知则直接进入分级 | 背景足以选择单位/指标；不在这里访谈完整销售流程 |
| G1 采购潜力 | 讲分配精力的用途，取单位、周期、普通量级，给一至五星表供校准 | 五档已确认或明确跳过；未知与零分开 |
| G2 历史贡献 | 解释累计成交金额，问普通订单金额/币种，再给五星表 | 档位和指标采用情况有记录；统计节点留给订单环节 |
| G3 成交次数 | 解释小额复购价值，给五星建议；说明一单分批只算一次 | 档位已确认或不采用，不要求客户自己编表 |
| G4 综合等级 | 简短建议取最高，再确定正常升降与错误纠正；说明等级将用于维护 | 当前采用指标、阈值及聚合明确；给一条“解释星级”的智能体指令 |
| P0 商机概念 | 用同客户两笔采购说明客户关系与商机不同；给新建/沿用规则 | 客户理解或明确调整采购划分 |
| P1 完整流程 | 读取客户已讲步骤，补最少业务背景；展示完整参考及每个结果的用途 | 客户看过并调整完整图/表；保存采用、可选、排除及待定节点 |
| P2 节点细化 | 只细化采用节点；逐个给进入依据、必要字段与具体选项 | 条件足够明确或有边界清楚的待定项；保留整张流程 |
| T1 商机跟进 | 先用一个已选阶段演练，再按完整已采用流程给提醒覆盖表供调整；仅细化需要提醒项，共用规则直接引用 | 每个已采用节点含可选环节均有需要/不需要/待定记录；需提醒项规则明确才算完成，待定可带着影响继续，不能只做报价就收工 |
| T2 停滞与结果 | 主动建议长期不回复/无推进的结束规则，结合采购周期确认适用阶段、时间与自动/人工方式；已有企业决定保留 | 输单原因单选为默认基建；规则与数据就绪时crm-fde配置Twenty期限工作流，交接实际版本供chat-signal二次复核 |
| O 订单衔接 | 在赢单定义清楚时说明建单与统计，可提前到 P2 后完成 | 一笔订单怎样影响累计金额、次数、评级已明白，不展开完整财务系统 |
| M 关系维护 | 先给一档周期供校准，再补其余星级；说明活跃商机优先、完成重计时 | 各档周期与任务生命周期明确，不预设高星必然高频 |
| R 简单归属 | 沿用已知人员，必要时确认谁负责；说明客户/商机/任务归属 | 责任清晰，未分配能识别；不顺势访谈账号接入、权限、公私海 |
| C 收拢蓝图 | 汇总字段、完整流程及规则；据此主动分析阶段、等级、提醒中可交给 Twenty 的确定性计算，拆开聊天事实提取与后续计算 | 每条采用规则有输入、触发、条件、动作、执行归属和依赖；只留影响实施的缺口，不重做问卷 |
| I 实施验收 | crm-fde 按授权完成 Twenty 及分析出的工作流配置、验证和启用，用代表性案例和真实回读验收 | 已分析、已配置、已验证、已启用分别有证据；不以蓝图代替部署，不把可实施工作流推给 chat-signal |
| L 自主调整 | 客户亲自提出一次低影响修改，理解影响并检查结果 | 记录实际练习和学习手册，不只问“懂了吗” |

O 可在赢单后立即衔接，P2 中的提醒可转 T1 后再回到尚未完成的节点；这种安排要保留当前位置和返回点，不重问已定内容。默认先完成分级再进入商机；客户主动选择先做流程时记录跳转，后续从原进度继续。

## 一轮怎样推进

1. 读当前步骤、待答问题、已确认规则和对应教材；必要时读 [连续教学示范](14-dialogue-walkthrough.md) 的当前段，沿用其教学动作。
2. 解释当前设计对客户工作的用途，提出适合其背景的具体建议，通常只留下一个决策问题。单位和量级等紧密相关输入可同问，不夹带另一模块的问题。
3. 客户回答后，提取决定并写入档案；给出简短含义/用途说明，进入本步骤下一问或下一个步骤。
4. 每个模块末尾简短展示本公司规则、下一步作用及一条可用的智能体指令；指令需出现在客户答复中，不只存入手册。不每轮复述全部表格。完整流程审阅是例外：宁可一张完整表，也不要为了简短丢节点。
5. 判断是否满足完成条件。必需业务事实才问；低影响选择给起步建议；技术事实用工具查；范围外内容记到扩展清单。遇到跳过记录具体影响，不变相追问。

客户说“不知道”：提供候选方案和一个容易比较的例子。说“可以”：只确认上一明确建议并前进。纠正某项：只修改该项及依赖，再回原位置。作者指出教材遗漏：修教材，不继续让作者扮演客户。

## 发出客户回复前的检查

- 这轮是否帮助客户理解一个管理设计，还是只索取信息？已经讲清的含义无需重复。
- 应当给的五档表、完整流程或规则建议是否已经在本轮客户可见的答复中？工具日志和进度消息不替代教学输出。
- 关键字段是否随本次决定说明“是什么、用来干什么、谁填写/怎么算”？后台技术标识不讲给客户。
- 是否在等待完整流程审阅时越过了它，开始问定金/交付细节？
- 是否保存了新的选择与当前位置？没有文件写入能力就明确尚未持久保存，不能只说“已记录”。

本页规定教学行为，不要求所有模型逐字背诵。客户应感受到连贯、自然、简短的解释；不暴露步骤编号或内部检查表。
